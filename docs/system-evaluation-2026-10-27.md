# Проверка ответов VIIO — 27 октября 2026

Система отвечает и соблюдает проверенные ограничения ролей, но качество ответов неоднородно. Автотесты прошли, а в живых диалогах обнаружены ошибки вычислений, переформулирования, поиска и выбора модели. Считать агент готовым к ответам без проверки пока нельзя.

## Объём и методика

- Основная модель: `qwen/qwen3-4b-2507`; coder: `qwen2.5-coder-1.5b-instruct`.

- 140 тестов API и 32 теста WebChat прошли. Проверка WebChat включает сборку сервера.

Итог по строгой оценке всего ответа: **25 успешных, 4 частичных, 6 неуспешных, 1 без достаточного эталона**. Повтор арифметического вопроса считается отдельным запросом. Это диагностическая выборка, а не статистическая оценка качества модели.

## Существенные проблемы

1. **Неверная арифметика воспроизводится.** Оба ответа `401`. Для точных вычислений нужен детерминированный вычислитель или отдельная проверка. Одной правкой инструкции надёжность не подтверждается.
2. **Маршрутизация всё ещё слишком широкая.** В `services/coding_agent.py` шаблон «измен…код» может захватывать «изменения структуры…Код не нужен». Исключение отрицания кода сейчас зависит от `needs_knowledge`. Нужен регрессионный тест полного запроса из JSONL.
3. **Короткие продолжения теряют контекст coder.** «Добавь проверку отрицательных значений аргументов…» не продолжило предыдущую функцию. Явный `/code` помог. Следует учитывать активную специализацию беседы, сохраняя проверку прав на каждом запросе.
4. **Поиск чувствителен к формулировке.** Документ `doc-b6b851d9` существует, но первоначальная формулировка его не вернула. Уточнение DocumentObject исправило результат. Нужна отдельная проверка поиска по названию и перефразированным вопросам.
5. **Ответ может потерять условие из документа.** Для отпуска рецептов источник `doc-9a1955c5` содержит `Used_Recipe.date_otp` и отдельную ветку платных рецептов `used_paid_recipe.dispense_date`. Агент назвал вторую универсальным ответом. Требуется оговаривать различия или уточнять тип рецепта.
6. **Источники оформляются ненадёжно.** Coder получил справочные сведения, правильно использовал значения, но показал внутреннее имя `knowledge_reference` вместо документа `doc-cbcd7191`.
7. **Общий поиск мешает задачам без документов.** Арифметика, научное объяснение и переформулирование выполняли поиск. В переформулировании появился ненужный абзац об отсутствии источников. Причинная связь с ошибкой вычисления этим тестом не доказана.

## Права, состояние и ограничения проверки

Запрос без внутреннего токена и анонимный запрос WebChat получили 401. Проверенные запреты coder и PostgreSQL сработали. У coder в проверенных диалогах нет вызовов инструментов. Это не полный аудит безопасности и не проверка всех комбинаций прав на каждый документ.

Временный пользователь удалён: основной прогон подтвердил удаление одной записи и тестовых историй; дополнительный прогон подтвердил удаление своих историй. Документы базы знаний не добавлялись и не изменялись. После проверки все пять контейнеров оставались healthy. Код приложения не менялся.

Память проверена только между двумя соседними сообщениями одной беседы. Долговременное резюмирование, перенос памяти между беседами, перезапуск приложения, массовая загрузка и PDF в этом прогоне не проверялись. Инструмент внешней PostgreSQL отключён (`PGSQL_ENABLED=false`), поэтому живое чтение схемы, EXPLAIN и оптимизация запросов на реальной базе не проверены. Нагрузочного теста и проверки всех 30 документов не было.

Время отдельных ответов до 15,08 с; первый запрос мог включать прогрев. Отказы в доступе занимали 0–0,02 с. Эти последовательные измерения нельзя использовать как оценку пропускной способности.

Сценарии используют текущие настройки работающего контейнера, создают временные истории и временного пользователя WebChat, затем удаляют их в `finally`. Нужны доступные модели, PostgreSQL, Qdrant и WebChat. Принудительное завершение процесса может помешать очистке. Ответы при повторе могут отличаться. Не перезаписывайте исходные результаты при новом прогоне.

В PowerShell и Linux сначала скопируйте оба сценария:

```sh
docker compose cp APIAgent/scripts/evaluate_live_20261027.py apiagent:/tmp/evaluate_live_20261027.py
docker compose cp APIAgent/scripts/evaluate_followup_20261027.py apiagent:/tmp/evaluate_followup_20261027.py
```

PowerShell:

```powershell
docker compose exec -T apiagent python /tmp/evaluate_live_20261027.py | Out-File tmp/evaluation-new.jsonl -Encoding utf8
docker compose exec -T apiagent python /tmp/evaluate_followup_20261027.py | Out-File tmp/evaluation-followup-new.jsonl -Encoding utf8
```

Linux:

```sh
docker compose exec -T apiagent python /tmp/evaluate_live_20261027.py > /tmp/viio-evaluation-new.jsonl
docker compose exec -T apiagent python /tmp/evaluate_followup_20261027.py > /tmp/viio-evaluation-followup-new.jsonl
```

Поля `summary.route_pass` и `validation.pass` проверяют только указанные технические свойства. Итоговую оценку смысла, полноты и источников нужно выполнять отдельно по эталонам; автоматический summary не заменяет таблицу выше.
