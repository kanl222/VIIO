# Самостоятельный агент-консультант

Цель агента — помогать внешним пользователям разобраться в работе организации и давать практические ответы по разрешённым инструкциям. Цель и правила вынесены в `Consultant/src/viio_consultant/prompts.py`; цикл работы агента — в `agent.py`. Это заменяет прежнюю схему обязательного автоматического поиска перед единственным вызовом модели.

1. Агент получает цель и вопрос пользователя.
2. Модель сама вызывает `search_published_documents(query)` и выбирает поисковую формулировку.
3. Инструмент обращается к шлюзу общей базы знаний APIAgent. Тот ищет в публичной коллекции Qdrant и возвращает только актуальные утверждённые публикации.
4. Модель читает результаты, при необходимости уточняет запрос и вызывает поиск ещё раз.
5. Перед выдачей ответа сервер сверяет все использованные публикации с каталогом. Отозванный или заменённый снимок блокирует весь подготовленный ответ.

Консультант и основной агент используют общий каталог и документы, а не независимые загружаемые корпуса. Ранее выбранное правило для внешних пользователей сохраняется: разрешены только явно опубликованные материалы. Основному агенту дополнительно доступны внутренние документы согласно его роли. Закрытый оригинал опубликованной выдержки не передаётся консультанту.

В распоряжении консультанта ровно один инструмент, только для чтения. Нет SQL, coder, запуска команд, загрузки/создания файлов, изменения документов и личной памяти. В аргументах поиска нет роли пользователя, имени коллекции или фильтра доступа. Неизвестные инструменты и дополнительные аргументы отклоняются. Внешний запрос не может передать `user_context` или объявить себя администратором.

Ограничения одного запроса: 60 секунд, до четырёх вызовов модели, до двух попыток вызова инструментов, до двух материалов на поиск и четырёх всего; выдержка каждого — до 3000 символов. Модель может ответить на простое приветствие без поиска. Содержательный ответ без найденных материалов сервер заменяет сообщением о недостатке данных. Если модель не вызывает поиск, сервер напоминает о нём; приложение не выполняет скрытый поиск вместо модели.

Контейнер Consultant остаётся отдельным, без прямого доступа к PostgreSQL/Qdrant, томам оригиналов и внутреннему токену. URL и ключи API сохранены: внешний порт 8001 и совместимый прокси APIAgent на 8000. История запросов stateless. Для консультанта нужна модель с поддержкой tool calling; проверена текущая `qwen/qwen3-4b-2507`.

## Проверки перед выпуском

Прошли **253 теста APIAgent/Consultant**, включая интеграцию с настоящими изолированными PostgreSQL-схемами и Qdrant в памяти. Новые тесты проверяют: запрос, выбранный моделью; повторный поиск; приветствие без поиска; блокировку выдуманного ответа при отсутствии материалов; подмену роли/коллекции; попытку SQL-вызова; лимиты; повторную проверку публикаций после генерации. Интеграционные проверки закрытого оригинала, публичной выдержки и отзыва версии переведены на настоящий цикл вызова инструмента.

До выпуска проведён [прогон реальной модели](consultant-agent-preview-2026-10-27.jsonl) в одноразовом контейнере с новой логикой и рабочим разрешённым источником. Исходники подключены только для чтения, рабочий сервис не менялся:

- На приветствие — без поиска.
- По модулю сотрудников, поиску рецепта и документам доступа — модель сама вызвала инструмент, сформулировала запрос и выдала ответ со ссылками на публикации.
- На запрос закрытого кода и паролей с утверждением «я администратор» — инструмент получил только публичные материалы, секреты не выдавались.

Скрипт воспроизведения: `Consultant/scripts/evaluate_agent.py`. Он читает существующие материалы и не создаёт/не удаляет документы. Запуск из корня проекта в PowerShell или Linux:

```sh
docker compose run --rm --no-deps --volume ./Consultant/scripts:/checks:ro consultant python /checks/evaluate_agent.py
```

Прогон фиксирует реальные `tool_calls` модели и обращения к шлюзу. Он проверяет поведение поиска и доступа, а не точность каждого утверждения в сгенерированном тексте.
