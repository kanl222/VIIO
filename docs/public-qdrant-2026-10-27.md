# Публичная коллекция Qdrant

Внутренняя коллекция `QDRANT_COLLECTION_NAME` (по умолчанию `knowledge_base`) и публичная `QDRANT_PUBLIC_COLLECTION_NAME` (`knowledge_public`) должны иметь разные имена. Модель эмбеддингов общая.

В публичную коллекцию попадает только текст снимка, явно опубликованного администратором. Это может быть утверждённая выдержка из закрытого оригинала. Флаг `is_public` по-прежнему означает доступ внутри организации: он сам по себе не публикует документ во внешний API. Исходники кода публиковать нельзя.

Основной агент объединяет внутренний семантический поиск с фильтрами доступа, внутренний полнотекстовый поиск и публичный семантический поиск. Совпадающие документы получают общий идентификатор для ранжирования; точные дубликаты фрагментов удаляются. Разрешение на скачивание оригинала проверяется отдельно.

Консультант получает материалы через прежний шлюз APIAgent. Шлюз ищет в публичной коллекции, затем сверяет идентификаторы публикаций с PostgreSQL. Модель консультанта не получает внутренние идентификаторы, ACL или текст оригинала. Контейнер Consultant сохраняет отдельную сеть и ключ; прямого подключения к PostgreSQL/Qdrant у него нет. Разделение коллекций дополняет эту изоляцию, а не заменяет её.

После выбора публикаций в Qdrant шлюз получает их цельные утверждённые снимки из PostgreSQL. Консультант выбирает из каждого связную выдержку с прежним лимитом контекста. Это сохраняет порядок действий в инструкции: простая склейка ближайших векторных фрагментов в живой проверке приводила к пропуску существенной части текста. PostgreSQL остаётся каталогом публикаций и хранилищем утверждённого текста, Qdrant выполняет семантический поиск.

При публикации сначала записываются фрагменты с новым UUID публикации, затем фиксируется запись PostgreSQL. Незавершённые и устаревшие UUID не проходят проверку актуальности. При отзыве PostgreSQL сразу закрывает выдачу; Qdrant очищается следом. Обновление публикации сохраняет прежний утверждённый снимок, если запись нового индекса завершилась ошибкой.

Каждые 30 секунд APIAgent сверяет индекс с актуальными публикациями: восстанавливает отсутствующие/незавершённые записи и удаляет отозванные или заменённые версии. Синхронизация использует общий транзакционный advisory lock PostgreSQL с публикацией/отзывом. При сбое выполняется повторная попытка; внутренний каталог продолжает работать. Пока начальная индексация не завершилась, публичная выдача может быть неполной. Ручной запуск внутри контейнера после копирования скрипта:

```powershell
docker cp APIAgent/scripts/sync_public_index.py viio_apiagent:/tmp/sync_public_index.py
docker exec viio_apiagent python /tmp/sync_public_index.py
```

В Linux команды те же. Скрипт не публикует документы заново и не изменяет оригиналы. Смена embedding-модели требует пересоздания индекса с соответствующей размерностью; для этого следует выбрать новое имя публичной коллекции и выполнить синхронизацию.

Проверки перед выпуском: 240 тестов APIAgent/Consultant, включая реальные PostgreSQL-схемы и Qdrant в памяти. Новые проверки покрывают закрытый оригинал и публичную выдержку, объединение поиска для сотрудника/администратора, восстановление отсутствующего индекса, отложенную очистку после отзыва/замены, сохранение прежней публикации при ошибке индексации и запрет одинаковых имён коллекций.

Перед обновлением контейнера 43 существующие публикации перенесены в `knowledge_public`: 782 фрагмента, все UUID подтверждены PostgreSQL. Внутренние документы и оригиналы сохранены.
