# Оценка ответов агентов по общей базе знаний

Дата: 28 октября 2026 года. Проверена реально запущенная сборка после выпуска A. Код, системные промпты, параметры моделей, индексы и документы для этого прогона не менялись.

**Вывод:** агенты самостоятельно обращаются к базе знаний, но ответы по рабочим операциям пока недостаточно надёжны. На 10 вопросах с документированным порядком действий средняя практическая оценка — **2,6/5 у Assistent и 2,2/5 у Consultant**. У каждого только 3 ответа получили оценку не ниже 4. Наличие ссылки или HTTP 200 не считалось доказательством правильности.

## Методика

Основной прогон: 16 одинаковых естественных вопросов каждому агенту, всего **32 ответа**. В запросах не было названий файлов, указаний «ищи в базе», имён инструментов, команд /code или /db, правильных выдержек и эталонных ответов. Эталонные тексты были сняты отдельно для оценки и не передавались агентам. Дополнительно выполнен один контрольный повтор вопроса о начальных остатках у обоих агентов — **ещё 2 ответа**, отдельно от основного результата.

Для 10 рабочих вопросов правильная инструкция присутствует в опубликованной части общей базы и доступна обоим агентам. Assistent отвечал как employee. Два дополнительных вопроса по внутреннему модулю отчётов задавались Assistent с ролью programmer; для Consultant там ожидается отказ из-за отсутствия этих сведений среди публикаций. Эти два сценария не включены в сравнение среднего балла по рабочим инструкциям.

Другие проверки: ложная предпосылка про SMS-код, выдуманный проект, запрос исходников/паролей, приветствие. Каждый основной запрос начинал новый диалог; запросы выполнялись последовательно. Настроенная модель у обоих — `qwen/qwen3-4b-2507`. Это небольшая функциональная выборка, а не нагрузочный тест или статистическая оценка точности всей системы.

Оценку выполнил Codex сверкой полных ответов с исходными текстами документов. Шкала: 5 — корректно и полно; 4 — полезный ответ с небольшими пропусками/добавлениями; 3 — частичный ответ либо существенные проблемы обоснования/источников; 2 — значимое смешение процедур; 1 — нет пригодного ответа при наличии инструкции; 0 — технический сбой или выдача запрещённых данных. Порог «пригоден без существенной правки» — 4. Оценки и обоснования доступны отдельно, поэтому их можно пересмотреть.

Оценивалась верность загруженным инструкциям, включая документы 2020–2024 годов. Актуальность описанных процедур относительно нынешних регламентов этим тестом не устанавливалась.

## Результаты основного прогона

| Показатель | Assistent | Consultant |
|---|---:|---:|
| HTTP 200 | 16/16 | 15/16 |
| Средний балл по 10 рабочим вопросам | 2,6/5 | 2,2/5 |
| Рабочие ответы с баллом ≥4 | 3/10 | 3/10 |
| Медиана успешного ответа | 13,27 с | 10,01 с |
| Самый долгий запрос, включая ошибки | 67,76 с | 33,66 с |
| Непустой структурированный список источников | 10/16 | 15/16 |

Первый запрос Assistent занял 67,76 с; причина этого выброса отдельно не профилировалась. Медиана не является показателем производительности при параллельной нагрузке.

По checkpoint-трассам Assistent поиск состоялся в 15 из 16 вопросов: **14 вызовов инициировала модель**, один — прикладной fallback на приветствии. Запрос запрещённых исходников был остановлен прикладной проверкой роли до поиска. Для Consultant подтверждены выдача опубликованных источников и обращения к gateway; точные аргументы его tool calls публичный API не возвращает, поэтому такая же количественная разбивка для него не заявляется.

## Доказанные проблемы

### 1. Ложное отсутствие сведений

- В [инструкции аптечного учёта](https://gosapteka56.ru/files/Farmkomitet/is_lo/docs_apt_uchet/01-instruct-23.05.22.pdf) есть раздел 2 «Ввод начальных остатков», страницы 15–21: создание документа через Администрирование → Документы ввода начальных остатков, выбор собственных товаров, заполнение организации/отделения/склада/финансирования, номенклатуры и серий. Оба агента не справились с вопросом. В контрольном повторе Assistent снова дал тот же отрицательный ответ; Consultant ответил HTTP 200 за 7,69 с, но тоже сообщил об отсутствии сведений. Основной HTTP 503 при этом не исключён из статистики.
- В [руководстве поиска рецептов](https://gosapteka56.ru/files/Farmkomitet/is_lo/docs_apt_uchet/05-rukovod.pdf), страницы 4–5, прямо описаны выбор одного из нескольких рецептов, подтверждение и подбор медикамента. Consultant заявил, что такого порядка в материалах нет.
- Внутренний документ «Модуля формирования отчетов ИСЛО 2.0», страница 2, содержит `(new AvailableReports())->getReportUser()` и источник `reports.get_report_parent_hierarchy`. Assistent не нашёл это на естественном вопросе. Тот же документ был найден на другом вопросе про `dateStart`, поэтому проблема не объясняется недоступностью документа для programmer.

### 2. Придуманные действия и смешение процессов

Для ручного поступления [раздел 3.1, страницы 22–34](https://gosapteka56.ru/files/Farmkomitet/is_lo/docs_apt_uchet/01-instruct-23.05.22.pdf) задаёт меню Управление запасами → Поступления товаров и обязательные реквизиты. Assistent вместо этого предлагает «Новую задачу» и дополнительные флаги без нужного порядка. Для отпуска в отделение Consultant превращает заголовки разделов инструкции в выдуманный путь меню.

В ответе о выборе электронного рецепта Assistent после правильных аптечных шагов добавляет вход старшей медсестрой, назначения и отпуск из места хранения отделения. Это сведения о другом процессе; сам факт наличия их в базе не делает их применимыми к вопросу.

### 3. Источники отображаются ненадёжно

У Assistent ответ по инвентаризации перечисляет материалы в тексте, но API возвращает `sources: []`. В ответе о COVID текст основан на специальной инструкции, а структурированный список содержит только модуль Медсестра. В `cited_sources` источники сопоставляются по строке названия; различия кавычек/пунктуации могут терять связь. В отрицательных ответах отдельный фильтр намеренно очищает структурированный список, но текстовые списки «подтверждающих» инструкций остаются.

У Consultant источник обычно есть, даже когда он не относится к вопросу: например, управление сотрудниками/МДЛП при вопросе о поступлении товара. Поэтому показатель «есть источник» нельзя использовать как качество ответа.

### 4. Таймаут поиска у Consultant

Единственная ошибка основного прогона — `ReadTimeout` в `HttpPublicationSource.public_search`, вызванном из search tool. Это сбой обращения к Documents, а не отсутствие инструкции. В работающем источнике задан HTTP timeout 10 с; общий лимит агента больше. Внутренняя причина задержки Documents/эмбеддингов этим тестом не установлена.

### 5. Приветствие запускает лишний поиск

На вопрос о возможностях Consultant выдаёт длинный сценарий администратора с адресом сети из уже опубликованного руководства. Это **не подтверждённая утечка закрытого документа** — адрес есть в разрешённой публикации, — но это нерелевантная выдача технических данных. У Assistent поиск в этом сценарии инициирован fallback приложения, а не моделью.

## Что исправлять сначала

1. Использовать этот набор как baseline. Сначала добиться нахождения разделов о начальных остатках, поступлениях, инвентаризации и дереве отчётов; оценивать правильные фрагменты отдельно от генерации.
2. Пересмотреть объединение результатов. Сейчас итоговая сортировка `rank_documents` основана на совпадениях слов; простого попадания в похожий документ недостаточно. Сравнить альтернативы на размеченных примерах, включая естественные перефразирования.
3. Исправить подбор контекста Consultant: сейчас `excerpt` выбирает окно до 3000 символов от первого найденного термина, часто заголовка/оглавления. Нужны релевантный раздел и соседние шаги внутри разрешённого снимка. Сохранять границу публикации и проверку её отзыва.
4. Не смешивать разные роли, программы и процедуры. Если правильный порядок не найден, сообщать об ограничении поиска, а не о доказанном отсутствии сведений во всей базе. При слабой выдаче — один ограниченный уточняющий поиск.
5. Связывать цитаты с проверенными идентификаторами материалов, а не точным воспроизведением длинного заголовка моделью. Список найденных материалов отделить от источников конкретных утверждений.
6. Измерить время стадий поиска/эмбеддингов и согласовать deadline источника с бюджетом Consultant. При временном сбое возвращать явный статус недоступности, не выдумывая процедуру. Приветствие обрабатывать без retrieval.

Промпт сам по себе не исправит выдачу, если нужный раздел не попал в контекст. До улучшения поиска ответы на рабочие операции по этой выборке следует сверять с инструкцией.

## Версия, сохранность и артефакты

Во время оценки появилась сторонняя правка `Consultant/src/viio_consultant/prompts.py`. Она не менялась и не развёртывалась в рамках этой задачи. Проверен промпт работающего контейнера: SHA256 `c49dae605460f90a0bcfb58c74a29880d55ff6e66fade5f8024f19490ee6b38b`, совпадает с закоммиченной версией до теста. Хеш нового файла в рабочем каталоге другой; оценка **не относится к ещё не развёрнутому новому промпту**.

Образы: Assistent `sha256:cc30bb143d8eb04987e0434e40d4c3b9a60c91cdc0f25f61a3f16f397e315bf9`; Consultant `sha256:df8a2b7afc8ef13db320185b6c948aae908822191bc5b6fc6328bfb8afed4e52`.

Сервисы были остановлены перед задачей и запущены в прежней production-конфигурации. Документы не создавались и не переписывались. После теста сверены 75 активных текстов, 43 текста/идентификатора публикаций и 49 контрольных сумм оригиналов: всё совпадает со снимком. Всего 79 версий документов. Собственные checkpoint-диалоги 16 основного прогона и 1 повтора удалены; оставшихся записей этих прогонов — 0. Закрытые исходники/пароли в контрольных ответах не выданы; это не полная проверка всех способов обхода доступа.
