# VIIO: администрирование и интерфейс

## Назначение

Продолжение существующего React-интерфейса: ассистент для сотрудников и административный раздел для управления пользователями и добавления знаний. Пользователь подтвердил назначение администратора учётной записи Admin; в текущей базе логин записан как `admin`.

## Direction contract

THESIS: административные задачи встроены в рабочее пространство VIIO. Приоритет — понятные действия, реальные данные и явные права доступа.

OWN-WORLD: сохраняются фиолетовый акцент, нейтральные светлая/тёмная темы, боковая навигация и Lucide. Общие переменные поверхностей, текста, границ и состояний находятся в `WebChat/src/index.css`. Новая визуальная идентичность не вводится.

STORY: администратор открывает вкладку в шапке, проверяет состояние, находит пользователя и изменяет его права либо добавляет документ с выбранной областью доступа.

FIRST VIEWPORT: общая шапка; слева навигация раздела; справа заголовок и пояснение, строка текущих счётчиков, состояние сервисов и переходы к действиям. На телефоне навигация становится горизонтальной, содержание — одноколоночным. Таблица прокручивается внутри своего контейнера.

FORM: функциональное расширение существующего приложения, Operate. Существующая структура и бренд сохранены; отдельный конкурс визуальных направлений не проводился.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.

## Функциональность

- Обзор: количество пользователей, диалогов, сообщений и неистёкших сессий; состояние базы и API агента; число фрагментов знаний. Обновление по кнопке.
- Пользователи: поиск, страницы по 20 записей, изменение роли и подразделений. Изменение ролей сериализуется транзакционной блокировкой, права инициатора перепроверяются; понижение последнего администратора отклоняется.
- Знания: вставка текста или чтение TXT/Markdown до 2 МБ, ограничение 500 000 символов, права сотрудникам / отделам / администраторам / всем. Документ индексируется существующим APIAgent. Просмотр и удаление уже загруженных документов в этот этап не входят: соответствующего API пока нет.
- Административный API проверяет сессию и роль admin. Парольные хеши и межсервисный токен не возвращаются клиенту. Публичная регистрация сохраняет employee/general.

- 19 тестов WebChat, включая отказ 401/403, безопасный список пользователей, защиту последнего администратора, права документа и недоступный агент.
- Проверка типов и production-сборка; Docker-сборка повторяет тесты на Linux.
- Браузер: 375×812 и 1440×960, обе темы; таблица, редактирование и сохранение прав, отправка документа на изолированных фикстурах. Тестовый сервер `WebChat/test/ui-preview.mjs` не обращается к рабочей БД и не включён в runtime-образ.

## Использование

Пошаговые действия для новой установки: [создание пользователя и первого администратора, назначение ролей, загрузка файлов](getting-started.md).

После входа пользователем с ролью admin открыть «Администрирование» в шапке. Для уже открытой сессии после назначения роли обновить страницу. Пароль и учётные данные не менялись.

Поддерживаемые роли редактора: employee, manager, programmer, admin. Роль programmer («Программист») даёт доступ к coder и документам сотрудников; роль admin также даёт доступ к coder. Подразделения вводятся через запятую. Доступ к документам по роли и подразделению объединяется по ИЛИ; администратор и автор сохраняют доступ.
