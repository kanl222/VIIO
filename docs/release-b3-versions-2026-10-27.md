# Версии документов

27 октября 2026. Продолжение каталога и массовой загрузки VIIO.

## Пользовательский процесс

В «База знаний» → «Каталог» нажать «История» рядом с номером версии. Открывается список версий с датами, отметкой актуальной версии и скачиванием сохранённых оригиналов. Для обновления выбрать один PDF, TXT или Markdown до 10 МБ.

Новая версия наследует название, владельца и права доступа документа. Обновление не меняет доступность документа для других ролей. История и загрузка новой версии доступны администратору. Разрешённое скачивание старых версий использует прежнюю проверку роли, отдела и владельца.

PDF сначала поступает на проверку текста. Пока новая версия готовится или ожидает проверки, поиск использует предыдущую. После успешной индексации новая версия становится актуальной; прежние оригиналы и поисковые записи сохраняются, но устаревшие записи исключаются из обычного поиска.

Повторная загрузка архивного файла как отдельного документа не восстанавливает старую версию автоматически. Для обновления выбрать актуальный документ в каталоге и загрузить новую версию через его историю.

## Хранение и переключение

- В каталоге добавлены `family_id` и `is_active`. Проверено исходное состояние: 30 документов, все версии 1. Миграция назначает каждому существующему документу собственное семейство.
- Уникальные индексы ограничивают номер версии в семействе и допускают не более одной актуальной версии.
- Номер и переключение сериализуются блокировкой семейства PostgreSQL. Две загрузки от одной исходной версии не перезаписывают друг друга: после первого успешного обновления второе задание получает сообщение об устаревшей исходной версии.
- Повтор одного задания использует тот же идентификатор новой версии и не добавляет повторную запись истории.
- Переключение сначала скрывает прежние записи поиска и открывает новые, затем подтверждает актуальность в PostgreSQL. Общей транзакции PostgreSQL/Qdrant нет; возможен короткий промежуток без результатов этого документа. При известной ошибке выполняется откат; при неопределённом исходе транзакции код проверяет каталог перед удалением записей.
- При запуске незавершённые переключения сверяются с PostgreSQL и восстанавливаются до запуска очереди. Недоступность внешних сервисов может потребовать повторного запуска или повтора задания после их восстановления.
- Основной каталог показывает актуальные документы; история возвращается отдельно. Архивные версии не увеличивают основной счётчик.

Добавлен внутренний маршрут `GET /api/v1/documents/versions/{doc_id}`. Для загрузки новой версии используется существующий `bulk-upload` с `version_parent_id` и одним файлом. Веб-сервер предоставляет административные маршруты; серверная обработка повторно проверяет исходную версию и наследует права из каталога.

## Проверки перед выпуском

**196 проверок API прошли**, включая настоящую PostgreSQL и локальный Qdrant с тестовыми embeddings. Добавлены проверки:

- новая версия доступна в поиске, архивная исключена;
- оригиналы обеих версий скачиваются без изменения байтов, права сохраняются;
- конкурентное обновление отклоняет устаревшую исходную версию;
- сбой активации возвращает предыдущую версию, повтор не дублирует историю;
- восстановление незавершённого переключения по каталогу;
- новая PDF-версия не заменяет прежнюю до подтверждения текста;
- ошибочная активация не убирает актуальную версию из каталога.

**43 проверки веб-сервера прошли**, включая ограничение истории администратором и передачу идентификатора документа с доверенным владельцем из сессии. TypeScript/Vite собраны.

Перед миграцией сохранён дамп `agent_db` в исключённый из Git каталог `tmp`. Применение сборки выполняется после коммита. Результат живого прогона фиксируется после обновления локальных контейнеров.

Сценарий `APIAgent/scripts/check_document_upload.py` поддерживает шаги `version` и `verify-version`: после исходной проверки загрузок создать новую версию, перезапустить APIAgent, проверить историю, оба оригинала, наследование доступа и поиск только по актуальной версии. Затем выполнить `cleanup`.

## Ограничения

Отзыв доступа для всего семейства, удаление, срок хранения, ручное восстановление старой версии одной кнопкой и отдельная внешняя публикация ещё не реализованы. Визуальная проверка истории в локальном браузере пока не выполнена. Это очередной этап общего плана, а не завершение всех улучшений.
