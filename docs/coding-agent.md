# Модель coder в VIIO

Консультант VIIO отвечает по базе знаний, отдельная модель coder пишет код прямо
в чат. В текущей установке `CODING_MODEL=qwen2.5-coder-1.5b-instruct`.
Coder получает задачу и переданный контекст и возвращает Markdown с кодом.
Ему не передаются инструменты: он не читает и не изменяет файлы, не запускает код,
не проверяет синтаксис, не обращается к БД. JSON в ответе остаётся обычным текстом.
Для работы с существующим кодом вставьте нужный фрагмент и требования в сообщение.

## Поиск перед написанием кода

Для задач о проекте, ИСЛО, SSRSReport или с явной просьбой использовать документы
сервер сначала ищет материалы в базе знаний, затем передаёт найденный текст coder.
Пример: `/code По базе знаний напиши Python-словарь типов отчётов SSRSReport.`
Для простой функции сложения без проектных сведений поиск не требуется.
Если пользователь явно называет документ в кавычках, поиск идёт по этому названию,
а соседние материалы исключаются из контекста coder. Если нужного названия нет
среди доступных результатов, система просит уточнить источник и не подменяет его другим.
Консультант также может передать инструменту `coding_agent` параметр `knowledge_query`
с конкретным запросом по схеме, правилам или примерам.

Поиск выполняется с текущими правами пользователя, а не от имени администратора.
Короткие уточнения внутри coder обновляют проектный контекст, если в недавней
истории есть соответствующая задача. При ошибке поиска система сообщает об этом,
вместо генерации неподтверждённого проектного кода. При отсутствии нужных сведений
coder должен запросить уточнение. Релевантность и точность ответа всё равно требуют проверки.

Два найденных фрагмента передаются только в текущий вызов модели, максимум 6000
символов по умолчанию. Исходные документы не добавляются к сохранённым сообщениям
coder и не переиспользуются как старый контекст следующего запроса. Сам coder
по-прежнему не выполняет поиск и не получает инструменты.
В метаданных ответа сохраняются размер переданного контекста и идентификаторы
найденных документов для проверки маршрута; полный текст справки туда не записывается.

## Доступ программистов и администраторов

Coder доступен пользователям с ролью `programmer` («Программист») или `admin` («Администратор»).
Руководитель и сотрудник без этих ролей получают отказ.
Администратор назначает роль в разделе «Администрирование → Пользователи → Роль».
Самостоятельно выбрать роль при регистрации нельзя. Существующие учётные записи
не переводятся в программисты автоматически.

Программист видит документы, разрешённые его роли, сотрудникам, его подразделению,
ему лично или всем. Документы только для руководителей и администраторов не
открываются без другого явного основания доступа.

Явные технические запросы направляются coder автоматически по словам и формулировкам.
У консультанта также есть инструмент `coding_agent` для передачи задач модели;
сама модель coder никаких инструментов не получает.
Для неоднозначных запросов и коротких продолжений используйте `/code`.

Обычная оптимизация отчёта или бизнес-процесса сама по себе не считается программированием. Разные диалоги coder могут обрабатываться параллельно; обращения к одной истории выполняются последовательно. Фактическая параллельность генерации зависит от сервера моделей. [Проверка обработки запросов](request-performance.md).

Примеры:

- `/code Напиши функцию add(a, b) на Python.`
- `/code Приведи содержимое sum.py с функцией сложения прямо в чате.`
- `/code Напиши SQL-запрос для таблицы products(id, name, price).`

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CODING_AGENT_ENABLED` | `true` | Подключить coder и `/code` |
| `CODING_MODEL` | пусто | Модель у текущего провайдера; пусто — имя модели консультанта с отдельными параметрами coder |
| `CODING_ALLOWED_ROLES` | `["programmer","admin"]` | Разрешённые роли; список можно сузить, остальные роли coder не допускает |
| `CODING_CONTEXT_MAX_CHARS` | `6000` | Максимальный размер текущего контекста из базы знаний |

После изменения настроек пересоздайте APIAgent. Папка исходников больше не подключается
к контейнеру и для работы coder не нужна. Существующие файлы пользователя сохраняются.

История coder сохраняется отдельно для каждого пользователя и диалога в PostgreSQL
(при его недоступности действует существующий переход к временной памяти).
Текстовый режим использует новый префикс истории `coder-text-`, чтобы старые вызовы
файловых инструментов не отправлялись модели без поддержки tools. Старая история
сохраняется в хранилище. Лимит запроса — 90 секунд, включая ожидание занятой модели.

## Промпт и генерация

Инструкции coder находятся в `APIAgent/src/apiagent/prompts.py`. Они задают формат кода, использование фактов из справки, уточнение отсутствующих сведений и текстовый режим без инструментов. Пример показывает применение значений справки непосредственно в реализации.

`CODING_TEMPERATURE`, `CODING_TOP_P` и `CODING_MAX_TOKENS` настраивают генерацию независимо от `CHAT_*`, даже при совпадающих именах моделей. Значения по умолчанию: `0.0`, `1.0`, `4096`. Полная таблица — в [руководстве](getting-started.md#настройки-генерации-моделей).
