# Проверка обработки запросов · 26.10.2026

Замечания проверены по текущему коду APIAgent. Устранены лишняя проверка коллекции Qdrant, общий замок coder и ложное направление обычной оптимизации отчётов к coder. Добавлены исключения для автоматического поиска и ограничение передаваемого контекста. Права поиска и раздельная история coder сохранены.

| Замечание | Результат проверки и изменение |
| --- | --- |
| Поиск для приветствий и `/code` | Отдельные приветствия, благодарности и прощания больше не вызывают автоматический поиск. «Привет! Как оформить отпуск?» продолжает искать документы. `/code` уже обходил основной граф через MultiAgentService; coder ищет справку только при необходимости. Дополнительно исключены команды специалистов на входе основного графа. |
| Три обращения к Qdrant | `collection_exists` перед поиском убран: обычный вопрос вызывает один поисковый запрос к Qdrant. Для распознанных сокращений остаётся дополнительный `scroll`, поскольку он улучшает нахождение точного названия документа. Проверка коллекции при индексации и подсчёте документов сохранена. |
| Синхронный инструмент блокирует event loop | Не подтвердилось: установленный StructuredTool.ainvoke запускает синхронный инструмент через `run_in_executor`. Тест реального ToolNode внутри скомпилированного графа подтверждает другой поток и работу event loop во время ожидания поиска. Инструмент не переписан без необходимости. |
| Общая очередь coder | Замок заменён замками по идентификатору истории пользователя и диалога. Разные истории обрабатываются параллельно; запись в одну историю остаётся последовательной. Замки освобождаются из слабого словаря после завершения держателей и ожидающих запросов. |
| Слишком широкий CODING_INTENT | Обычные «Оптимизировать отчёт о продажах» и «Оптимизируй запрос на отпуск» больше не считаются программированием. Явные SQL, код и алгоритмы продолжают направляться coder. Явный `/code` сохраняет приоритет. |
| Квадратичный обход истории | Не подтвердилось: несколько проходов и проверки множества уже давали O(n). Удалён дополнительный поиск позиции вопроса. Тест на 2 000 сообщениях ограничивает число посещений элементов линейной величиной. Это не ограничение размера самой истории. |
| Контекст без лимита | Общий бюджет автоматического поиска задаётся `RAG_CONTEXT_MAX_CHARS=12000` (от 1 000 до 48 000). Он общий для всех автоматических результатов текущего хода. Сам вопрос не обрезается, исходные сообщения checkpoint не меняются, старые автоматические результаты не возвращаются в промпт. У coder остаётся отдельный `CODING_CONTEXT_MAX_CHARS`. |

## Проверки

Все **140 тестов APIAgent** прошли. Добавлены 24 проверки пропуска поиска, маршрутизации, параллельности, последовательной записи одной истории, отмены ожидающего запроса, освобождения замков, работы event loop, ограничения контекста и количества вызовов Qdrant.

Проверены исчезновение и последующее создание коллекции без отрицательного кэша. Ошибки доступа и сервера не подменяются пустой выдачей. Предыдущие проверки ACL, обновления прав на следующем ходе, отдельных историй coder, загрузки PDF и PostgreSQL также прошли. Архитектурная проверка не выявила новых нарушений или циклов.

Число обращений проверялось на встроенном Qdrant с подсчётом реальных методов клиента. Проверки параллельности используют события синхронизации, а не предположения о длительности ответа модели. Указанные в исходном списке потери 200–600 и 50–150 мс не измерялись; конкретное ускорение на работающем сервере не заявляется. Производительность генерации зависит также от очереди и возможностей сервера моделей.

После обновления APIAgent проверен поиск в действующей коллекции через настроенную модель эмбеддингов: обычный вопрос вернул 5 фрагментов при 1 поисковом вызове и 0 проверках существования; вопрос про ИСЛО вернул 5 фрагментов при 1 поисковом вызове и 1 обращении по названиям. Данные коллекции при этой проверке не изменялись.

## Настройка

В корневом `.env` при необходимости добавьте:

```dotenv
RAG_CONTEXT_MAX_CHARS=12000
```

Применение на Windows PowerShell и Linux Bash из корня проекта:

```text
docker compose up -d --build --no-deps apiagent
```

Этот бюджет ограничивает автоматически добавленную справку, а не всю историю и не пользовательский текст. Дополнительные вызовы инструментов по инициативе модели по-прежнему возможны.

## Источники проверки библиотек

- [StructuredTool.ainvoke](https://reference.langchain.com/python/langchain-core/tools/structured/StructuredTool/ainvoke): дополнительно проверен исходный код установленной версии с fallback `run_in_executor`.
- [Qdrant: диагностика скорости поиска](https://skills.qdrant.tech/qdrant-search-speed-optimization/SKILL.md): диагностика отделяет сетевые расходы клиента от нагрузки сервера. Настройки индексов и фильтры ACL в этом изменении не ослаблялись.
