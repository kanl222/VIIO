# LangGraph tools/MCP: разбор статьи и применение к VIIO

> Обновление 26.10.2026: по новому решению пользователя coder доступен ролям `programmer` и `admin`. Описанные ниже результаты относятся к прежнему ограничению. Актуальные правила: [настройка coder](coding-agent.md).

Проверено 26.10.2026. Это техническая справка к статье Habr 949376, без воспроизведения её текста. Версии зависимостей статьи не установлены; актуальная документация не доказывает, что исторический пример никогда не работал.

1. **Привязка и исполнение разделены.** `bind_tools` передаёт модели определения пользовательских инструментов; ответ содержит запросы `AIMessage.tool_calls`. Функции исполняет приложение/агентный цикл. Результат связывается с запросом через `ToolMessage.tool_call_id == tool_call["id"]`. Для такого сценария требуется модель с поддержкой tool calling. Встроенные инструменты провайдера с исполнением на его стороне — отдельный случай. [Models](https://docs.langchain.com/oss/python/langchain/models#tool-calling), [Workflows and agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents).

2. **Маршрутизация — отдельная логика.** `ToolNode` исполняет инструменты; условное ребро направляет выполнение к инструментам либо `END` по наличию запросов модели. Это роли, для которых используют `ToolNode`/`tools_condition`; точную доступность второго имени следует проверять по закреплённой версии. Обычный строковый результат `end_session` становится содержимым `ToolMessage`, сам по себе граф не завершает. Если цикл проверяет имя запрошенного инструмента, остановку обеспечивает эта проверка, а не возвращённая строка. [Workflows](https://docs.langchain.com/oss/python/langgraph/workflows-agents), [Tool return values](https://docs.langchain.com/oss/python/langchain/tools#tool-return-values).

3. **`add_messages` работает по ID.** Новые сообщения добавляются; сообщения с существующим ID обновляются. Семантическое устранение одинаковых текстов из этого не следует. Объявление `Sequence` также не является механизмом сокращения истории или гарантией экономии памяти: это вывод об отсутствии такого поведения в описанной модели состояния. [Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api#working-with-messages-in-graph-state).

4. **MCP API зависит от поколения библиотеки.** Официальный старый импорт — `from langchain_mcp_adapters.client import MultiServerMCPClient`; импорт из `langgraph_mcp` документацией не подтверждён. Подтверждены `stdio` и Streamable HTTP (`http` в примере конфигурации), `get_tools()` и явная `session(...)`. Текущая документация уже предлагает `langchain.mcp.MCPAdapter` (beta, `langchain[mcp]>=1.4.0`); у него получение инструментов управляет сессией, вызовы инструментов открывают отдельные сессии. Нельзя переносить lifecycle одного API на другой без проверки версии. [Официальная миграция](https://docs.langchain.com/oss/python/migrate/langchain-mcp-adapters).

5. **`InMemorySaver` — память процесса.** Это checkpointing между вызовами в живом процессе, без сохранения после его перезапуска. Для production документация рекомендует checkpointer с базой данных. Называть его долговечным хранилищем некорректно. [Memory](https://docs.langchain.com/oss/python/langgraph/add-memory#use-in-production).

6. **Безопасность реализует приложение.** Host управляет разрешениями и согласием, сервер обязан проверять входы и доступ; клиенту рекомендованы подтверждения чувствительных операций. Описания поведения и annotations недоверенного сервера нельзя считать политикой безопасности. Следствие: запрет в промпте не заменяет программную авторизацию. [MCP Architecture](https://modelcontextprotocol.io/specification/2025-11-25/architecture), [Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#security-considerations), [Security principles](https://modelcontextprotocol.io/specification/2025-11-25#security-and-trust-safety).

7. **Оговорка об устаревании.** В LangGraph v1 `create_react_agent` deprecated в пользу `langchain.agents.create_agent`. Миграционный пример использует `prompt`, новый API — `system_prompt`; совместимость `state_modifier` без версии не установлена. Это не требование мигрировать собственный `StateGraph`. [LangGraph v1](https://docs.langchain.com/oss/python/migrate/langgraph-v1), [LangChain v1](https://docs.langchain.com/oss/python/migrate/langchain-v1#static-prompt-rename).

## Что показывает статья

[Статья Amvera на Habr](https://habr.com/ru/companies/amvera/articles/949376/) объясняет цикл вызова инструментов, подключение MCP, память, потоковую выдачу и разделение работы между агентами. Полезнее всего для VIIO идея явного процесса: получить сведения, передать специалисту контекст, подготовить ответ.

В опубликованных фрагментах есть ограничения; автор предупреждает, что полные примеры вынесены отдельно:

- Проверка пути через `str(full).startswith(str(WORKDIR))` пропускает соседнюю папку с похожим именем. Локальная проверка без записи файлов: `work-other/report.txt` проходит строковый префикс `work`, но не проверку принадлежности пути. Нужны разрешение пути, проверка его принадлежности и ограничения файлового доступа; одна проверка не защищает от гонок с символьными ссылками. [pathlib](https://docs.python.org/3/library/pathlib.html#pathlib.PurePath.is_relative_to).
- Описание `sqlite_query` как SELECT-инструмента не запрещает другие SQL-операторы: показан обычный `execute`. Нужны программные ограничения и соединение только для чтения. [sqlite3](https://docs.python.org/3/library/sqlite3.html#sqlite3.Cursor.execute).
- В показанном `node_data` предыдущее резюме не включено в сообщения специалисту явно. Общая история родителя не означает автоматическую передачу контекста каждому агенту.
- Постоянные `thread_id` вида `research` и `data` нельзя копировать в многопользовательский сервис с общим checkpointer: идентификаторы должны разделять пользователей и задачи.

## Сопоставление с VIIO

Ниже — выводы по локальному коду на 26.10.2026, а не требования статьи.

| Механизм | Текущее состояние |
| --- | --- |
| Отдельная модель для кода | Граф coder создаётся с `tools=[]`: [композиция](../APIAgent/src/apiagent/__init__.py). |
| Доступ только программистам | Проверка роли `programmer` выполняется в `CodingAgentService.chat`: [сервис](../APIAgent/src/apiagent/services/coding_agent.py). |
| Данные перед написанием кода | Сервис вызывает поиск с контекстом текущего пользователя и передаёт результат через `reference_context`; граф добавляет его к входу модели: [граф](../APIAgent/src/apiagent/services/graph_builder.py). |
| Разделение истории | История coder использует хеш идентификаторов пользователя и диалога; предусмотрен PostgreSQL checkpointer с резервной памятью процесса при недоступности БД. |
| Уточнения после ответа | Прямой выбор coder зависит от `/code` или признаков программирования в текущем сообщении. Короткое «добавь обработку ошибок» может уйти основному агенту; постоянного выбора специалиста здесь нет. |
| Потоковая выдача | [Маршрут WebChat](../WebChat/server/routes/chatRoutes.ts) возвращает готовый JSON-ответ. |

## Приоритеты дальнейшей работы

1. Хранить выбранного специалиста и текущую задачу в состоянии диалога. Добавить проверку сценария: запрос к coder → короткое уточнение → продолжение той же задачи. Повторно проверять роль на каждом обращении.
2. Сделать передачу контекста явной: задача, доступные источники, найденные факты, ограничения и результат поиска. При обязательном источнике без результатов возвращать запрос на уточнение.
3. Добавить пользователю статусы «поиск сведений → подготовка кода → ответ» через потоковую выдачу, фильтруя служебные данные и содержимое документов.
4. Подключать MCP при появлении конкретной внешней системы. Проверки доступа и исполнение оставлять серверному слою. Наличие MCP не добавляет модели поддержку tool calling.

Ограничение coder сохраняется: только подготовка кода в чате, без инструментов создания файлов и запуска. Для этих рекомендаций менять модель coder не требуется. Любая автоматическая проверка исполнением — отдельное изменение с отдельным объёмом полномочий.

В рамках исследования изменён только этот документ. Проверены локальные точки интеграции и отдельно воспроизведён дефект строковой проверки пути; поведение сервиса и ответы моделей заново не тестировались.
