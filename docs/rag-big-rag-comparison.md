# Сравнение VIIO с Big RAG, 25 октября 2026

Изучен исходный код `D:/Source/lm_studio_big_rag_plugin`. Подтверждены настройки по умолчанию: 512 слов, перекрытие 100 слов, пять результатов, порог 0,5; найденный текст вставляется непосредственно в пользовательский запрос. Фактические настройки ранее работавшего экземпляра плагина не найдены.

## Изменения VIIO

- Обязательный поиск выполняется до генерации содержательного ответа с текущими правами пользователя. С 26.10.2026 отдельные приветствия и благодарности пропускают автоматический поиск; `/code` обрабатывается отдельным coder с подготовкой справки по необходимости. [Проверка производительности](request-performance.md).
- Автоматически найденный контекст передаётся модели вместе с текущим вопросом. Исходный вопрос и результат поиска сохраняются в истории без изменения. Старые автоматические результаты поиска не включаются в следующие запросы к модели; предыдущие ответы диалога сохраняются.
- Добавлено разбиение по словам с сохранением переносов строк. Настройки: `RAG_CHUNK_UNIT=words`, `RAG_CHUNK_SIZE=512`, `RAG_CHUNK_OVERLAP=100`.
- Повторно извлечён текст 30 исходных PDF; перед обработкой сверены SHA256 с отчётом импорта. Идентификаторы документов и права скопированы из исходного индекса. OCR не применялся.
- Активная коллекция: `knowledge_base_big_rag_20261025`, 40 фрагментов. Исходная `knowledge_base` с 228 фрагментами сохранена.

## Проверка и ограничения

45 тестов APIAgent прошли. На пяти диагностических вопросах оба индекса нашли ожидаемый документ в первых пяти результатах в трёх случаях. Это небольшая проверка, а не доказательство общего улучшения поиска. Не найдены ожидаемые источники для вопросов «Как узнать, где и когда обслужен рецепт?» и «Какие типы документов есть в ИС ЛО?».

При одинаковом вопросе об ИСЛО и одинаковых мелких фрагментах модель с передачей контекста через результат инструмента сомневалась в определении системы. Прямая передача тех же фрагментов дала ответ «информационная система “Лекарственное обеспечение”». При крупных фрагментах модель дополнительно описала модуль отчётов. Один сравнительный прогон не гарантирует точность остальных ответов. Порог 0,5 не перенесён: его необходимо проверять на размеченных вопросах в текущей системе.

Машиночитаемый отчёт с вопросами, источниками и тремя ответами: [rag-big-rag-comparison-2026-10-25.json](rag-big-rag-comparison-2026-10-25.json).

Для дальнейшей оценки поиска используется принцип сравнения с ожидаемыми источниками из [официального руководства Qdrant](https://qdrant.tech/documentation/search-evaluation/retrieval-relevance/). При расширении набора следует отдельно оценивать нахождение документов и фактическую обоснованность ответа.

## Откат

В корневом `.env` задать `QDRANT_COLLECTION_NAME=knowledge_base`, `RAG_CHUNK_UNIT=characters`, `RAG_CHUNK_SIZE=500`, `RAG_CHUNK_OVERLAP=50`, затем пересоздать только APIAgent: `docker compose up -d --no-deps apiagent`. Прямая передача контекста останется включена. После добавления новых документов в активный индекс перед откатом потребуется перенести их: старый индекс не синхронизируется автоматически.
