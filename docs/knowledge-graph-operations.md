# Граф знаний: загрузка и резервное копирование

Исходные JSON находятся только локально в `data/knowledge_graph/`. В Git исключена вся папка `/data/`, включая резервные копии. Сами исходные данные, персональные сведения и локальные манифесты исправлений не следует добавлять в коммиты. Свежему клону репозитория необходимо отдельно предоставить разрешённый комплект JSON.

## Проверка и загрузка

Команды выполняются из корня проекта в PowerShell:

```powershell
& .\.venv\Scripts\python.exe scripts/attach_knowledge_to_graph.py --validate-only
& .\.venv\Scripts\python.exe scripts/backup_knowledge_base.py --output data/backups/kb-before-update-YYYYMMDD-HHMM
& .\.venv\Scripts\python.exe scripts/attach_knowledge_to_graph.py --uri bolt://127.0.0.1:7687
```

Загрузчик проверяет все ветки до подключения к Memgraph. Все узлы создаются перед связями; запись выполняется одной транзакцией. Повторная загрузка использует `MERGE`. При ошибке записи транзакция откатывается. Обычная загрузка обновляет свойства и добавляет связи, но не удаляет данные, отсутствующие в JSON.

Для проверенного удаления ошибочных сущностей и объединения старых идентификаторов используется дополнительный параметр `--reconcile-manifest <локальный JSON>`. Пример структуры с условными данными:

```json
[
  {
    "old": {"label": "Document", "key": "id", "value": "legacy-id"},
    "target": {"label": "Document", "key": "id", "value": "canonical-id"}
  },
  {"old": {"label": "Product", "key": "id", "value": "demo-only-id"}}
]
```

При наличии `target` входящие и исходящие связи переносятся к единственному целевому узлу. Без `target` старый узел удаляется вместе со связями. Манифест применяется в той же транзакции после создания узлов и до создания связей из JSON. Поэтому перед его использованием обязательны резервная копия и проверка каждой указанной сущности. Не формируйте удаления автоматически по сходству фамилий или названий.

## Состав копии

`scripts/backup_knowledge_base.py` требует Docker, локальную `.env` и работающие PostgreSQL, Memgraph, Qdrant и сервис документов. Каталог назначения должен отсутствовать. Скрипт сохраняет:

- `agent_db.dump`, `user_db.dump` — дампы PostgreSQL в custom-формате; проверяется чтение оглавления `pg_restore`;
- `memgraph.json` — все узлы, метки, свойства и ориентированные связи;
- `qdrant-*.snapshot` — снимок каждой коллекции, включая пустые; `qdrant-aliases.json` — псевдонимы;
- `documents.tar.gz` — содержимое `/data/documents` сервиса документов;
- `knowledge_graph/` — копию локальных исходных JSON;
- `manifest.json` — время UTC, размеры, SHA-256 файлов и счётчики.

Пароли и API-ключи не записываются в манифест. Копия содержит внутренние документы и пользовательские данные: храните её локально с ограниченным доступом. Это последовательные снимки разных хранилищ, а не единая межсервисная транзакция. Для строго согласованной копии на рабочем сервере на время операции следует остановить приём новых загрузок и другие записи. Redis, конфигурация, роли PostgreSQL и индексы/ограничения Memgraph в эту логическую копию не входят.

## Восстановление

Сначала проверяйте SHA-256 по `manifest.json` и восстанавливайте копию в изолированное окружение. Не направляйте восстановление на работающую БЗ без отдельного плана переключения.

Для графа предусмотрен скрипт, который откажется писать в непустую БД:

```powershell
& .\.venv\Scripts\python.exe scripts/restore_knowledge_graph.py data/backups/<копия>/memgraph.json --uri bolt://127.0.0.1:17687
```

Он восстанавливает метки, свойства и связи одной транзакцией; внутренние ID узлов могут измениться. Ограничения и индексы необходимо создать отдельно из схемы приложения. Скрипт рассчитан на локальный Memgraph без аутентификации.

Дампы PostgreSQL восстанавливаются `pg_restore --exit-on-error --no-owner` в заранее созданные пустые БД. Передавайте бинарный дамп через файловый дескриптор Python либо `docker cp`, чтобы PowerShell не перекодировал его. Коллекции Qdrant восстанавливаются из соответствующих snapshot-файлов штатным механизмом Qdrant, после чего отдельно восстанавливаются псевдонимы. Архив оригиналов распаковывается в том документов остановленного сервиса. Сверяйте число документов, точек и связей после восстановления.
