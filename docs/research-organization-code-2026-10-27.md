# Исходный код организации как контекст VIIO

Дата проверки: 27.10.2026. Исследование публичных первичных источников; исходники организации во внешние сервисы не передавались. Ниже отдельно указаны подтверждённые возможности и предлагаемые решения VIIO. Интеграция не выполнена.

## 1. Разбирать код с учётом структуры

**Документировано.** Tree-sitter строит синтаксическое дерево, поддерживает инкрементальное обновление и работает с частично ошибочным кодом. Доступны грамматики Python, JavaScript, TypeScript, C#, Java и других языков. Это синтаксический анализатор, а не готовый анализатор зависимостей всего проекта. [Tree-sitter](https://tree-sitter.github.io/tree-sitter/)

Готовый `LlamaIndex CodeSplitter` использует дерево синтаксиса и ограничивает размер фрагментов символами или токенами. Однако на текущую реализацию есть открытое сообщение: `chunk_lines` и `chunk_lines_overlap` объявлены, но не влияют на разбиение. Перед внедрением нужно закрепить версии и проверить поведение своими примерами; обещать заданное перекрытие по строкам нельзя. [API и исходный код](https://developers.llamaindex.ai/python/framework-api-reference/node_parsers/hierarchical/), [issue #23027](https://github.com/run-llama/llama_index/issues/23027)

**Предложение VIIO.** Хранить фрагменты функций/классов вместе с сигнатурой, docstring, необходимыми импортами и контекстом класса. Слишком большие функции делить по блокам с пределом токенов. SQL, шаблоны, конфигурации и Markdown требуют отдельных правил. При отсутствии подходящей грамматики использовать ограниченное текстовое разбиение и явно отмечать сниженное качество. Не считать каждый AST-узел отдельным полезным фрагментом автоматически.

## 2. Точное происхождение и обновление

**Документировано.** Ссылка на ветку меняется вместе с её содержимым. GitHub рекомендует commit ID для постоянной ссылки и поддерживает ссылки на строки. `git diff` позволяет сравнивать два коммита, получать имена и статусы изменённых файлов. [Постоянные ссылки](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files), [git diff](https://git-scm.com/docs/git-diff)

**Предложение VIIO.** Метаданные: `repository_id`, commit SHA, путь, язык, символ, диапазон строк, hash содержимого, ACL и версия индексатора. Обновлять изменённые файлы; удалённые файлы удалять из индекса, переименованные учитывать. Публиковать новый снимок после успешной индексации, чтобы не смешивать несовместимые версии. Инкрементальный парсер сам по себе не реализует этот процесс.

В ответе показывать «репозиторий → файл → строки → версия» с проверенной сервером ссылкой. ID чанков, оценки векторов и внутренние маркеры оставлять в диагностике.

## 3. Поиск по символам и смыслу

**Документировано.** GitHub Code Search поддерживает точные строки, регулярные выражения и ограничения `repo:`, `path:`, `language:`, `symbol:`. Это подтверждает полезность отдельного точного поиска для идентификаторов. Поиск символов не заменяет полнотекстовый поиск употреблений. [Синтаксис GitHub Code Search](https://docs.github.com/en/search-github/github-code-search/understanding-github-code-search-syntax)

**Предложение VIIO.** Сначала искать точные имена методов, таблиц, полей, ошибок и путей; параллельно — семантически подходящие объяснения. Объединять кандидатов и ограничивать контекст. Комментарии на русском, запросы на русском и английские идентификаторы проверять отдельным набором задач: структурный парсер не гарантирует качество многоязычных embeddings. Для начала достаточно гибридного поиска и метаданных; необходимость GraphRAG должна подтверждаться измерениями.

## 4. Права и исключения

**Документировано.** GitHub ищет приватные репозитории только для пользователей, уже имеющих доступ. При этом его индекс исключает vendor/generated, бинарные и некоторые крупные файлы; поиск не является исчерпывающим. `.gitignore` не распространяется на уже отслеживаемые файлы. Gitleaks умеет проверять директории и историю Git, но его отсутствие находок не доказывает отсутствие всех секретов. [Ограничения GitHub](https://docs.github.com/en/search-github/github-code-search/about-github-code-search), [gitignore](https://git-scm.com/docs/gitignore), [Gitleaks](https://github.com/gitleaks/gitleaks)

**Предложение VIIO.** Разрешать код программисту и администратору, дополнительно проверять доступ к конкретному проекту. Фильтровать до передачи контекста модели, повторять проверку при открытии файла. Исключать секреты, `.env`, ключи, дампы, сборки, зависимости и бинарные файлы отдельной политикой. Проверять секреты до embeddings, включая локально отслеживаемые файлы. Изменение ACL должно немедленно закрывать поиск, ссылки, кеш и повторное использование контекста.

## 5. Совместимость с coder без инструментов

**Предложение VIIO.** Сервер получает разрешённый снимок репозитория, выбирает контекст и передаёт coder задачу плюс короткие выдержки. Coder пишет код только в чат. Доступ к диску, Git, исполнению и поиску остаётся у серверного слоя. Комментарии и README считать данными, а не инструкциями агента.

Пилот: один репозиторий и один язык; задачи на поиск метода, изменение интерфейса, использование внутреннего API, устаревший commit и запрет доступа. Измерять точность найденного файла/символа, корректность ссылок, работоспособность предложенного кода и отсутствие утечек. Открытые компоненты выше — строительные блоки, а не готовая безопасная корпоративная система.
