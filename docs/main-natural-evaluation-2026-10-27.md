# Основной агент: вопросы без подсказок об инструментах

Дата: 27 октября 2026. Проверен работающий основной HTTP-сервис, без изменения промптов, маршрутизации или документов. Скрипт: `APIAgent/scripts/evaluate_main_natural.py`; полный журнал вопросов, ответов и происхождения вызовов: `main-natural-evaluation-2026-10-27.jsonl`.

## Метод

14 отдельных разговоров: приветствие, естествознание, арифметика, редактура, ИСЛО, список отчётов, AvailableReports, деловая задача, неизвестный проект, подключённая PostgreSQL, Python, SQL, запрет coder для сотрудника и попытка обхода доступа. Ни в одном запросе нет команд `/code`, `/db`, названий инструментов или указаний искать в базе знаний. Роли передавались через доверенный внутренний API; это не повторная проверка авторизации веб-интерфейса.

После ответа прочитаны сохранённые сообщения основного агента и coder. Вызовы с идентификатором `knowledge-*` создаёт узел приложения `prepare_search`; остальные tool calls классифицируются как выбор модели. Наличие состояния coder фиксирует выполнение отдельного маршрута, но само по себе не доказывает делегирование моделью. Наблюдения сопоставлены с текущим `graph_builder.py`, `database_agent.py` и регистрацией инструментов в приложении.

## Результаты

- Все 14 запросов завершились HTTP 200. Это доступность API, а не 100% правильных ответов.
- 6 вызовов `search_knowledge_base`: ИСЛО, список отчётов, AvailableReports, продажи, неизвестный проект, PostgreSQL. Все 6 созданы приложением. Вызовов инструментов, выбранных моделью, в этих разговорах **0**.
- Приветствие, объяснение движения Земли, редактура и арифметика обошлись без инструментов. Арифметика вернула правильное `600`; вычисление выполняется приложением.
- Python и SQL переданы coder автоматически. Получены корректные простые тексты `return a + b` и `SELECT id, name FROM products WHERE price > 100;`. В этом прогоне код не исполнялся, проведена ручная проверка этих коротких выражений.
- Сотруднику отказано в coder; попытка получить скрытые исходники также закончилась отказом. Проверена конкретная пара запросов, а не полная матрица доступа.
- На неизвестный проект «Янтарь-98417» агент не придумал руководителя или дату. Однако API приложил пять нерелевантных найденных материалов как sources.
- Вопрос об оптимизации отчёта о продажах не ушёл в coder. Ответ безопасный, но мало полезный: вместо уточнения цели агент перечислил отсутствие сведений в материалах.

## Выявленные проблемы

1. **Автономный выбор инструментов не подтверждён.** Без подсказок пользователя поиск работает, но его запускает сервер. Нельзя называть это самостоятельным выбором модели. Для отдельной проверки способности модели выбирать инструменты потребуется явно обозначенный эксперимент без автоматического предварительного поиска.
2. **Подмена задачи при ответе о списке отчётов.** Агент предложил `getReport()` и `findOne(report_path)`, возвращающие один отчёт, хотя пользователь просил список. Ответ про AvailableReports отдельно упоминает `getReportUser()` для дерева отчётов. Требуются проверка по первоисточнику и исправление качества ответа; наличие ссылки не доказывает правильность.
3. **Естественный вопрос о подключённой PostgreSQL не вызвал инструмент БД.** Он ушёл в поиск документов. PostgreSQL сейчас выключена (`pgsql_enabled=false`); выполнение реального чтения не проверялось. Кроме того, текущий DatabaseAgentService включается только через `/db`, а инструмент PostgreSQL не зарегистрирован среди инструментов основного графа. В ответе агент не объяснил отключение интеграции. Никакие настройки или подключения ради теста не менялись.
4. **Источники выдаются и при отсутствии ответа.** Для неизвестного проекта и вопроса о PostgreSQL sources содержат нерелевантные документы. Нужно отделять найденных кандидатов от источников, действительно подтверждающих ответ.

## Ограничения и дальнейшие действия

Это один последовательный прогон текущих настроек, без нагрузочного теста и статистики повторяемости. Сведения об ИСЛО не получили независимой полной экспертной оценки; автоматический процент фактической точности не вычислялся. Служебные разговоры удалены (14 основных и соответствующие coder/route checkpoints), документы не менялись.

Следующий шаг: предоставить основному агенту контролируемый инструмент делегирования чтения PostgreSQL с проверкой роли; сравнить автоматический поиск и выбор инструмента моделью на одинаковом наборе вопросов; проверять соответствие ответа вопросу и подтверждение каждой ссылки. Эти изменения в рамках данного тестирования не выполнялись.
