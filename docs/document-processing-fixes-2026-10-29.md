# Проверка обработки документов — 29 октября 2026

Продолжение `research-document-parsers-2026-10-29.md`. Проверено текущее рабочее дерево с уже имевшимися изменениями интеграции Docling. Изменения предыдущей работы сохранены.

## Исправления этого прохода

- `Documents/src/viio_documents/services/office_extraction.py`: таблицы DOCX/ODT экспортируются цельными Markdown-таблицами вместо абзацев с разделителем `|`. Первая строка используется как шапка. При разбиении длинной таблицы сохраняются границы строк и повторяется шапка. Внутренние вертикальные черты экранируются, переносы внутри ячейки представлены `<br>`, пустые столбцы сохраняются.
- `Documents/src/viio_documents/services/document_chunks.py`: соседний раздел без тела больше не пропадает при следующем заголовке того же или более высокого уровня. Строки с вертикальными чертами внутри ограждённого блока кода не выделяются в отдельную таблицу. Версия разбиения — `sections-v2`.
- Добавлены пять регрессионных проверок в `Documents/tests/test_document_structure_regressions.py`; обновлена документация сервиса.

## Проверка

До исправления новые проверки потери пустого раздела и разрыва блока кода дали ошибки (`FF`). После исправления проверки этих случаев и таблиц DOCX/ODT прошли.

Полный набор содержит 80 проверок. В общем прогоне с отдельным PostgreSQL 79 прошли; оставшаяся проверка памяти агента остановилась на отсутствующем пути к Windows-библиотеке `pywintypes`. После подключения существующей среды Assistent через `site.addsitedir` эта проверка отдельно прошла: `1 passed`. Изменять продуктовый код ради окружения тестов не потребовалось.

PostgreSQL запущен во временном контейнере без рабочих томов. Тесты создают собственные случайные схемы, используют Qdrant в памяти и временные оригиналы. Проверены очередь, сохранение оригинала, ручное подтверждение текста PDF, версии, публикации и ограничения доступа. Рабочий каталог и индекс не переиндексировались.

В работающем `viio-pdf-worker-1` выполнено реальное CPU-распознавание синтетического одностраничного русского скана. Успешно распознаны «Инструкция», «лекарств», «Сохраните», числа `25` и `12345`; возвращены `engine=docling-cpu`, `pages=1`, структурный `document`, 147 символов Markdown. Эта проверка подтверждает работоспособность OCR на контрольном скане, но не качество всех страниц реального корпуса.

Повторное сканирование Sentrux Documents: `quality_signal` 5512 → 5513. Это диагностическая метрика, не оценка качества OCR.

## Применение и ограничения

Работающие сервисы не пересобирались. Для применения исправлений требуется обновить образ Documents с той конфигурацией Compose, которая используется при запуске. Уже подготовленный текст не меняется автоматически: материалы DOCX/ODT нужно повторно извлечь, проверить и проиндексировать, а исправления разбиения применить повторной индексацией. Массовая перезапись рабочего индекса в эту проверку не входит.

Пилот на 5–8 реальных оригиналах из исследования остаётся отдельной проверкой качества: полнота шагов, оглавление, многостраничные таблицы, сложные сканы и связь страниц с итоговыми фрагментами. Положение фрагментов после ручной правки нельзя достоверно восстановить из старых координат Docling; текущие метаданные сохраняют путь разделов, а исходный структурный JSON — журнал задания.
