## Что исправлено

1. В основном приложении модель первой получает возможность выбрать поиск или `coding_agent`. Если она пропустила необходимый поиск либо делегирование программирования, приложение выполняет запасной вызов. Черновой ответ без необходимого инструмента пользователю не возвращается. Программный построитель графа сохраняет прежний режим для совместимости; основной сервис явно включает новый режим.
2. На один ход установлен предел в три вызова инструментов, включая параллельные. Повторное обращение модели сверх бюджета не выполняется. Результат coder возвращается прямо в чат, без дополнительного переписывания основной моделью. Coder остаётся без инструментов; `/code` и продолжения активной задачи сохраняют прямой маршрут.
3. Естественные вопросы о подключённой PostgreSQL распознаются до обычного поиска. Роль проверяется до модели и подключения. Выключенная интеграция получает явный ответ об отключении. Для включённой БД основная модель в отдельном неперсистентном графе выбирает операцию чтения; результаты не сохраняются в историю. Произвольный вопрос без упоминания подключённой БД не гарантирует выбор этого маршрута; `/db` остаётся точным способом обращения.
4. В основном ответе `sources` фильтруется по названиям действительно упомянутых найденных материалов. При сообщении об отсутствии сведений список пуст. Это консервативная фильтрация атрибуции, **не семантическая проверка каждого утверждения**. Coder сохраняет отдельную семантику списка предоставленных материалов.
5. Лексический поиск выбирает фрагмент по покрытию значимых слов с учётом частоты и вариантов русских окончаний, а не по самому раннему совпадению. Фрагменты ограничены по длине. ## Оставшиеся ограничения качества

HTTP 200 не считается доказательством правильности. Ссылки на документы также не гарантируют подтверждение каждой фразы. Например, ответ о `dateStart` правильно называет `DateTime`, но дополнительно сближает его с `start_date` из другого примера — это требует предметной проверки. Для открытого вопроса об оптимизации продаж ответ остаётся мало полезным: вместо уточнения цели модель перечисляет отсутствие сведений. Эти случаи не объявлены идеальными или полностью решёнными.

Полная экспертная оценка всех утверждений, многократная статистическая оценка, нагрузка и новый прогон OCR через Docling не выполнялись. Автоматические проверки загрузки, PDF и сохранения документов входят в полный API-набор.

Финальный прогон основного агента удалил собственные 19 разговоров и связанные coder/route checkpoints (два запроса использовали одну историю). Прогон внешнего консультанта удалил четыре собственные загрузки и публикации. Существующие документы намеренно не изменялись.
