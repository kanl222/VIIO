# Проверка PDF и отмена загрузок

27 октября 2026. Продолжение первого этапа каталога и массовой загрузки.

## Что изменилось

Массово загруженный PDF теперь сначала проходит извлечение текста и получает статус **«Требует проверки»**. До подтверждения администратором его текст не индексируется. Это правило действует и для текстовых PDF, и для результата распознавания Docling.

Администратор открывает текст, исправляет ошибки и нажимает **«Подтвердить и добавить в базу»**. Система ставит утверждённый текст в очередь индексации с исходными правами документа. Исходные байты PDF сохраняются отдельно; исправление текста их не меняет. В поисковых метаданных сохраняются обработчик, число страниц, идентификатор проверяющего и дата подтверждения.

Это добавление во внутреннюю базу знаний. Отдельный процесс публикации материалов внешнему консультанту ещё не реализован.

## Как пользоваться

1. Администратор открывает «База знаний» → «Массовая загрузка» и отправляет файлы.
2. TXT и Markdown проходят обычную индексацию. Для PDF дождаться статуса «Требует проверки».
3. Нажать «Проверить текст», прочитать и при необходимости исправить содержание.
4. Нажать «Подтвердить и добавить в базу» и дождаться статуса «Готово».
5. Для задания в очереди или на проверке доступна кнопка «Отменить загрузку». Уже начавшаяся обработка не отменяется: сервер возвращает конфликт состояния. Отменённое задание не подхватывается рабочим процессом и не возобновляется кнопкой повтора; для нового импорта нужно выбрать файл заново.

Закрытие формы проверки не отменяет задание. Проверка остаётся доступна после повторного открытия страницы и перезапуска APIAgent. Неподтверждённые задания не занимают рабочие процессы очереди.

Оригиналы и записи отменённых заданий сохраняются. Автоматическое удаление по сроку хранения и ограничение общего занимаемого места пока не добавлены.

## Состояния и защита от гонок

```text
TXT/MD: queued → processing → ready | error
PDF:    queued → processing → needs_review → queued → processing → ready | error
        queued | needs_review → cancelled
```

Изменения состояния выполняются условным обновлением PostgreSQL. Подтвердить можно только актуальную проверку с её токеном версии. Повторное подтверждение или отправка формы после отмены возвращают HTTP 409. Если задание уже забрал рабочий процесс, отмена также возвращает 409.

Данные проверки хранятся в `document_upload_jobs.review`. При запуске выполняется добавочная миграция: существующие задания и статусы сохраняются, ограничение допустимых состояний расширяется. Список статусов не возвращает тексты проверок; текст загружается отдельно для выбранного задания.

Маршруты веб-приложения доступны только администратору. Идентификатор проверяющего веб-сервер берёт из сессии, игнорируя поля и параметры браузера. Внутренний API продолжает доверять серверному контексту, защищённому межсервисным токеном.

## API

Во внутреннем API добавлены:

- `GET /api/v1/documents/bulk-review/{task_id}` — получить актуальный текст проверки.
- `POST /api/v1/documents/bulk-review/{task_id}?reviewer_id=...` — подтвердить `{content, review_token}`.
- `POST /api/v1/documents/bulk-cancel/{task_id}` — отменить ожидающее задание.

Веб-сервер предоставляет соответствующие административные маршруты с префиксом `/api/admin/documents`. Пользователи остальных ролей не получают доступ к этим операциям.

## Проверки

- **190 проверок API прошли**, включая настоящую PostgreSQL в отдельных временных схемах: переход в проверку без индексации, утверждённый текст после пересоздания рабочего процесса, сохранность оригинала, отказ при неверном токене, повторном подтверждении и подтверждении отменённого задания, запрет отмены начавшейся обработки, миграция старой схемы без потери задания.
- **41 проверка веб-сервера прошла**: запрет проверки и отмены для анонимного пользователя и сотрудника; проверяющий берётся из сессии; лишние поля браузера не передаются; ответы 409 сохраняются.
- Сборки TypeScript/Vite и Docker прошли.
- Живая система: загружены TXT, Markdown, два PDF, повреждённый PDF и неподдерживаемый файл. Оба корректных PDF остановились на проверке. После настоящего перезапуска один PDF подтверждён, второй отменён; готовы три документа, повреждённый файл получил отдельную ошибку. Проверены исходные байты и отказ в скачивании сотруднику. Пять тестовых заданий и связанные тестовые документы удалены по идентификаторам прогона.
- Перед обновлением сохранён дамп `agent_db` в локальный исключённый из Git каталог `tmp`. В предыдущем этапе отдельно проверялось восстановление дампа; восстановление именно нового дампа в этом прогоне не повторялось.

Тест использовал текстовый PDF с обработчиком pypdf. Проверка качества OCR реальных сканов и измерение производительности Docling CPU остаются отдельными задачами. Форма проверки прошла сборку; визуальный прогон формы в локальном браузере не выполнен.

Сценарий живой проверки `APIAgent/scripts/check_document_upload.py` теперь запускается в порядке `begin` → `prepared` → перезапуск APIAgent → `verify` → `cleanup`. Служебный файл `/tmp/viio-upload-check.json` должен сохраниться между шагами.
