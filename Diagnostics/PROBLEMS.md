# Сводный реестр проблем: трассировка, диагностика и качество работы агентов VIIO

*Дата фиксации: 28 октября 2026 года*  
*Связанные документы: `docs/agent-diagnostics-2026-10-28.md`, `docs/agents-kb-evaluation-2026-10-28.md`, `docs/retrieval-inspection-2026-10-28.md`*

## 1. Проблемы с системой трассировки и локальной диагностики (Почему «нет трассировки»)

### 1.1. Режим Opt-in: трассировка не ведётся при обычном запуске Docker
* **Суть проблемы:** Трассировка в кодовой базе VIIO полностью опциональна и изолирована. В базовых файлах `docker-compose.yml` и `docker-compose.prod.yml` переменная `VIIO_TRACE_DIR` не определена, тома для трасс не смонтированы, а контейнер `viio_diagnostics` отсутствует.
* **Следствие:** Если контейнеры поднимаются стандартной командой `docker compose up -d`, агенты (`assistent` и `consultant`) не записывают ни одного файла трассы. В коде проверка `if not enabled(): return` срабатывает молча.
* **Решение:** Обязательно указывать файл оверлея диагностики при запуске:
  ```powershell
  docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.diagnostics.yml up -d --build assistent consultant document-worker documents diagnostics
  ```

### 1.2. Недоступность Docker Desktop / демона Docker на хосте
* **Суть проблемы:** На Windows-хосте фоновая служба Docker Desktop или WSL2 может быть остановлена. При попытке вызова Docker возвращается ошибка именованного канала:
  `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine: The system cannot find the file specified`.
* **Следствие:** Ни один контейнер системы (включая агентов, PostgreSQL, Qdrant и сайт диагностики на порту 3010) не работает.
* **Решение:** Запустить Docker Desktop и дождаться перехода демона в статус «Engine running».

### 1.3. Локальный запуск на Windows без Docker (неверные пути по умолчанию)
* **Суть проблемы:** В `Diagnostics/server.py` зашиты пути по умолчанию для Linux-контейнера:
  ```python
  ROOTS = [Path(p) for p in os.getenv('TRACE_ROOTS', '/traces/main,/traces/consultant').split(',')]
  REVIEWS = Path(os.getenv('REVIEW_ROOT', '/data/reviews'))
  ```
* **Следствие:** Если разработчик запускает `python server.py` напрямую на Windows, пути `/traces/main` и `/traces/consultant` резолвятся в несуществующие папки в корне диска (`D:\traces\...` или `C:\traces\...`). Сервер стартует без ошибок, но список трасс на `http://localhost:3010` всегда пустой (`items: []`).
* **Решение:** При запуске на хосте вручную передавать переменные среды:
  ```powershell
  $env:TRACE_ROOTS = "D:\Source\VIIO\tmp\traces\main,D:\Source\VIIO\tmp\traces\consultant"
  $env:REVIEW_ROOT = "D:\Source\VIIO\tmp\reviews"
  python Diagnostics/server.py
  ```
  А агенту указывать: `$env:VIIO_TRACE_DIR = "D:\Source\VIIO\tmp\traces\main"`.

### 1.4. Отсутствие ретроспективной трассировки
* **Суть проблемы:** Коллектор `collector.py` работает как синхронный перехватчик событий в момент выполнения HTTP-запроса (`POST /api/v1/chat` или `POST /api/v1/consultant/chat`). Он не выгружает данные из истории переписки в PostgreSQL.
* **Следствие:** Старые запросы, отправленные до включения `VIIO_TRACE_DIR`, невозможно увидеть в веб-интерфейсе. Сразу после запуска сайта список трасс пуст («Пока нет запросов»). Трасса формируется только после отправки нового запроса к агенту.

### 1.5. Подавление ошибок записи трассы в агентах
* **Суть проблемы:** В соответствии с архитектурным контрактом сбой сохранения трассы не должен прерывать ответ пользователю. Поэтому в `collector.py` блок записи обёрнут в `except Exception: logger.warning(...)`.
* **Следствие:** Если том переполнен, указан несуществующий путь или у процесса нет прав на запись (например, несовпадение UID 65532 в контейнере), агент успешно отвечает пользователю, но файл трассы не создаётся, а ошибка видна только в логах контейнера.

### 1.6. Защита Loopback / Host / Origin
* **Суть проблемы:** Сервер `server.py` проверяет заголовки запроса:
  - `Host` должен быть строго `localhost:3010`, `127.0.0.1:3010` или `[::1]:3010`.
  - Для POST-запросов (сохранение оценок и эталонов) проверяется `Origin`.
* **Следствие:** Попытка открыть сайт по внешнему IP-адресу машины или через нестандартный reverse proxy завершается ошибкой `403 Forbidden: Откройте сайт через localhost:3010`.

### 1.7. Лимиты хранения и усечение содержимого
* **Суть проблемы:**
  - Автоматическая ротация удаляет файлы трасс старше 7 дней и сохраняет не более 1000 последних запросов на агента.
  - Текстовые поля свыше 100 000 символов усекаются с пометкой `[Обрезано журналом после 100000 символов]`.
  - При превышении суммарного размера трассы в 8 МБ события сбрасываются и заменяются сообщением `capture_limit`.

## 2. Проблемы качества ответов агентов (по результатам оценки 28.10.2026)

*По итогам тестирования 10 документированных рабочих регламентов средняя оценка ответов составила: **2.6/5 у Assistent** и **2.2/5 у Consultant**. Пригодными признаны лишь 3 из 10 ответов у каждого агента.*

### 2.1. Ложное отрицание наличия сведений (False Absence)
* **Ввод начальных остатков:** В инструкции аптечного учёта `01-instruct-23.05.22.pdf` есть раздел 2 (стр. 15–21), подробно описывающий меню «Администрирование → Документы ввода начальных остатков». Оба агента заявили, что инструкции по начальным остаткам в базе нет.
* **Выбор из нескольких рецептов:** В руководстве `05-rukovod.pdf` (стр. 4–5) прямо описана процедура выбора одного из нескольких найденных рецептов. Consultant заявил об отсутствии регламента.
* **Дерево отчётов разработчика:** Внутренний метод `AvailableReports->getReportUser()` описан в документации модуля отчётов. Assistent для роли `programmer` не смог найти этот метод при естественном вопросе.

### 2.2. Галлюцинации интерфейса и придуманные шаги
* **Ручное поступление товаров:** Вместо описанного в регламенте пути «Управление запасами → Поступления товаров» Assistent предлагает нажать «Новая задача» и выставляет выдуманные флаги.
* **Отпуск в отделение:** Consultant берёт заголовки разделов инструкции и синтезирует из них несуществующий пункт меню в ИС ЛО.

### 2.3. Смешение несвязанных процессов и ролей
* При вопросе об отпуске медикаментов Assistent начинает правильно описывать действия аптечного сотрудника, а затем переключается на инструкцию старшей медсестры (вход под другой ролью, списание с мест хранения отделения).

### 2.4. Ненадёжная привязка источников (Citations & Sources)
* **У Assistent:** Часто в тексте ответа документы перечисляются, но структурированное поле API `sources: []` возвращается пустым. Это связано с тем, что механизм привязки сравнивает точные строки заголовков (разница в кавычках/пробелах ломает связь) или отфильтровывает источники при негативном ответе.
* **У Consultant:** Противоположная проблема: консультант прикрепляет источники к 100% ответов, даже если найденный документ абсолютно нерелевантен (например, инструкция МДЛП прикрепляется к ответу о приёме сотрудника).

### 2.5. Сетевые таймауты Consultant (ReadTimeout)
* При обращении к шлюзу документов `HttpPublicationSource.public_search` установлен жесткий таймаут клиента httpx 10 секунд. При задержке расчёта эмбеддингов или тяжелом поиске запрос консультанта падает с HTTP 503 / 504.

### 2.6. Лишний поиск при простых сценариях
* На обычное приветствие («Здравствуйте», «Что ты умеешь?») Consultant запускает тяжелый поиск по базе, находит опубликованную инструкцию администратора и выдаёт пользователю внутренний сетевой адрес сервера.

## 3. Проблемы подсистемы поиска и формирования контекста (Retrieval & Context)

### 3.1. Недостаточная глубина семантических кандидатов
* Целевые разделы документов при векторном поиске в Qdrant часто оказываются за пределами top-k:
  - Раздел «Ввод начальных остатков» находится на **39-м месте** в приватной коллекции и на **365-м** в публичной.
  - Раздел «Инвентаризация» — на **28-м и 468-м** местах.
  - При текущих лимитах отбора (top-15 для приватной коллекции, top-40 для публичной) семантический поиск физически не доходит до нужных фрагментов.

### 3.2. Деградация при повторном ранжировании (`rank_documents`)
* Алгоритм переранжирования считает буквальное вхождение отдельных слов запроса: +3 за слово в тексте, +5 в заголовке.
* Исходный семантический скор Qdrant и ранг полнотекстового поиска (FTS) в формуле не учитываются.
* В результате точные совпадения редких терминов (таких как `getReportUser` или `ФИФО`) вытесняются нерелевантными документами с большим количеством общеупотребительных слов.

### 3.3. Засорение контекста дубликатами (полная книга + части)
* В базе одновременно хранятся полные инструкции и их разрезанные части. `rank_documents` воспринимает их как независимые документы и заполняет все слоты top-5 одной и той же инструкцией в разных версиях, вытесняя другие полезные материалы.

### 3.4. Отсутствие гибридного поиска у Consultant
* Публичный шлюз консультанта использует только векторную ветку Qdrant. В отличие от основного агента, у консультанта векторный поиск не объединяется с резервным текстовым поиском SQL/FTS.

### 3.5. Ошибочный срез окна контекста у Consultant (`excerpt`)
* Consultant извлекает окно до 3000 символов от первого найденного слова запроса.
* В большинстве длинных документов первое вхождение слова находится в оглавлении или аннотации в начале файла. В результате агент получает оглавление, а сам пошаговый алгоритм, расположенный на 15–20 страницах, отрезается.

### 3.6. Превышение бюджета контекста у Assistent
* Заданный лимит `RAG_CONTEXT_MAX_CHARS=12000` применяется только к автоматическим сообщениям `knowledge-*`.
* При прямых вызовах инструментов моделью размер переданного текста составляет от **12 969 до 20 371 символов**, что перегружает окно модели и ухудшает внимание к деталям.

## 4. Сводная матрица проблем и рекомендуемых действий

| № | Компонент | Проблема | Симптом | Решение |
|---|---|---|---|---|
| **1** | Diagnostics / Docker | Opt-in режим | Нет записей на :3010 | Запускать с `-f docker-compose.diagnostics.yml` |
| **2** | Diagnostics / Local | Linux-пути по умолчанию | Пустой список трасс на Windows | Передавать `$env:TRACE_ROOTS` и `$env:REVIEW_ROOT` |
| **3** | Host / Daemon | Docker не запущен | Ошибка npipe канала | Запустить службу Docker Desktop |
| **4** | Consultant / Gateway | Срез 3000 симв. от первого слова | Потеря регламентов (остатки, рецепты) | Выделять окно вокруг целевого заголовка/раздела |
| **5** | Retrieval | Ранжирование по числу слов | Вытеснение точных терминов (`getReportUser`) | Учитывать семантический скор и ранг FTS в `rank_documents` |
| **6** | Retrieval | Малая глубина top-k | Нужные части на 39–468 местах | Увеличить глубину первичной выборки Qdrant |
| **7** | Assistent / Sources | Потеря списка источников | `sources: []` в ответе API | Сопоставлять источники по ID документов, а не по строке заголовка |
| **8** | Consultant / HTTP | Таймаут 10 с | HTTP 503 ReadTimeout | Увеличить таймаут `public_search` до 30 с |
| **9** | Prompts / Router | Поиск на приветствие | Выдача внутренних IP-адресов | Добавить жесткий guard: отключать retrieval при greeting |
| **10** | Assistent / Tokenizer | Превышение лимита контекста | До 20 000 символов в tool context | Применять единый лимит 12 000 символов ко всем путям |
