# Локальная диагностика агентов VIIO

Отдельный React + TypeScript сайт по адресу **http://localhost:3010**.
Сервер использует стандартную библиотеку Python и не получает ключи VIIO
или доступ к рабочим базам данных. Подключение опубликовано только на `127.0.0.1`.
Защита Host и Origin запрещает чтение через подменённый домен и запись с чужих сайтов.

## Что видно

Верхние вкладки разделяют журнал: **Агенты**, **OCR**, **Поиск**.
Вкладка OCR показывает запрос и результат в одном обращении:
параметры, размер и SHA-256 оригинала; затем извлечённый текст, страницы,
движок, структурный JSON Docling и ошибки. При фоновой загрузке видны имя файла
и номер задания. Бинарный оригинал и служебные ключи в трассу не копируются.
Вкладка поиска показывает обращения к внутренней БЗ и к шлюзу одобренных
публикаций, запрос, кандидатов после проверки доступа и итоговый отбор.
Отображаются детальные метрики современного RAG:
- Ветки поиска: **По смыслу (Dense)**, **BM25 (Sparse)** на базе `Qdrant/bm25`, **По словам** (лексика каталога) и **Публичный индекс**.
- Переранжирование: исходный ранг RRF и точные скоры Cross-Encoder ONNX модели (`bge-reranker-v2-m3`).
- Индикация кэширования: бейджи попадания в кэш Redis.
- Контекстное расширение Small2Big (Sentence-Window): индикатор связного контекстного окна предложения, коэффициент расширения (`ratio`) и объём добавленных символов (`expanded_chars`).
После выделения RAG поисковые трассы пишет контейнер `rag` в отдельный том
`rag_traces`; сайт читает его через `/traces/rag` без права записи. Старые трассы
Documents остаются доступны.
Записываются завершённые обращения; старые события OCR/поиска не восстанавливаются.

- Журнал завершённых запросов основного агента и консультанта: вопрос, время,
  результат выполнения, число обращений к поиску и модели.
- Маршрутизация, запросы инструментов, разрешённые кандидаты, итоговый отбор,
  фактические сообщения модели, её видимый результат и окончательный ответ.
- У консультанта отдельно показаны поиск публикаций, выбор двух публикаций
  и извлечение отрывков до 3000 символов.
- Ошибки отдельных веток поиска, проверки актуальности доступа, настройки модели
  из разрешённого списка и хеш системного промпта.
- Эталонный ответ, точная фраза источника, ID нужного документа, оценка 1–5,
  ручная отметка этапа ошибки и заметки. Эти данные не отправляются агентам.
- Буквальная проверка наличия фразы в кандидатах, отборе, входе модели и ответе.
  Она не определяет смысловую правильность ответа.
- Сравнение сохранённых ответов на одинаковый вопрос и экспорт выбранной трассы в JSON.
- Сводка текущей выборки: ошибки выполнения, p50/p95 времени, ручные оценки
  и распределение отмеченных причин.

Отсутствующее событие обозначается как отсутствие данных. Старые запросы без
диагностики не восстанавливаются, скрытые рассуждения и служебные ключи не записываются.
Публичный шлюз экспортирует только одобренные тексты публикаций, без внутренних оригиналов.

Большие тексты этапов и фрагментов отображаются только после раскрытия соответствующего
блока и убираются из DOM при его закрытии. Проверка фразы и экспорт JSON используют
полную загруженную трассу независимо от раскрытых блоков. Автообновление журнала
пропускает скрытую вкладку и ожидает завершения предыдущей загрузки; ручное обновление
остаётся доступным. Обновление журнала не перезагружает выбранную трассу и форму разбора.

## Запуск с Docker

```powershell
docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.diagnostics.yml up -d --build assistent consultant document-worker documents diagnostics
```

Два агента, API документов и обработчик пишут каждый в свой том, сайт читает их без права записи. Разборы хранятся
в третьем томе. Отключение сайта не останавливает агентов; ошибка записи трассы
не должна ломать ответ. Без `VIIO_TRACE_DIR` агент не записывает диагностику.
Сборка консультанта использует текущие исходники; не включайте в неё незавершённые
изменения промпта, если хотите сохранить работающую конфигурацию.

Коллектор удаляет трассы старше 7 дней и оставляет не более 1000 запросов каждого
агента при записи следующего запроса. Оценки сохраняются отдельно и автоматически
не удаляются. Журнал содержит вопросы и тексты документов, поэтому рассчитан
на доверенный локальный компьютер. Экспорт JSON включает эти тексты.

`collector.py` — исходник небольшого адаптера наблюдения. Его копии находятся
в пакетах `assistent.services.diagnostics`, `viio_consultant.diagnostics` и
`viio_documents.services.diagnostics` для независимой сборки сервисов;
после изменения нужно синхронно обновить все копии.

Для обновления только документов и сайта диагностики, без пересборки моделей агентов:

```powershell
docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.diagnostics.yml build rag document-worker diagnostics
docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.diagnostics.yml up -d --no-deps rag document-worker documents diagnostics
```

Для локального запуска без Docker включите каталоги документов в `TRACE_ROOTS`
наряду с каталогами агентов и задайте `VIIO_TRACE_DIR` отдельно процессам Documents.
Ограничения коллектора общие: до 100 000 символов в строковом поле и 8 МБ на трассу.
Усечение и превышение лимита отмечаются явно. Структурный JSON может содержать
текст документа, поэтому журнал предназначен для доверенного локального доступа.

## Разработка

```powershell
cd Diagnostics
npm ci
npm run build
```

Для запуска без Docker задайте `TRACE_ROOTS` (список каталогов через запятую),
`REVIEW_ROOT` и выполните `python server.py`: по умолчанию он слушает только
`127.0.0.1:3010`. `npm run dev` запускает React на `127.0.0.1:5174`
с локальным прокси к серверу на 3010.

Проверки из корня проекта:

```powershell
python -m unittest discover -s Diagnostics/tests -v
```

Сначала требуется сборка React. На Windows ограниченная среда запуска может
блокировать локальные соединения, необходимые `asyncio` и HTTP-тестам.
