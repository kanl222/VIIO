# VIIO WebChat

Веб-чат на React 18 и Vite с сервером Express. Пользователи, сессии, диалоги и сообщения хранятся в PostgreSQL (`user_db`). Сервер передаёт сообщения в APIAgent и добавляет межсервисный токен из `INTERNAL_API_KEY`.

## Запуск

Пошаговая инструкция для Windows и Linux, создание первого администратора и загрузка файлов: [руководство VIIO](../docs/getting-started.md).

Из корня проекта:

```powershell
docker compose up -d --build webchat
```

Локально из каталога `WebChat`:

```powershell
npm ci
npm run build
npm start
```

По умолчанию сервер слушает `0.0.0.0:3000`. Настройте `HOST`, `PORT`, `AGENTAI_URL`, `INTERNAL_API_KEY` и подключение к PostgreSQL через переменные окружения или `.env` в каталоге `WebChat`. База данных и APIAgent должны быть запущены отдельно.

Для разработки запустите `npm run server` (сборка и запуск Express), а в другом терминале — `npm run dev` (Vite на порту 5173 с проксированием `/api` на порт 3000).

## Проверки и сборка

- `npm test` собирает TypeScript-сервер и запускает тесты HTTP API и регрессионные проверки чата. В тестах внешние сервисы и база заменяются тестовыми подменами.
- `npm run build` проверяет типы клиента и собирает клиент в `dist/`, сервер — в `dist-server/`.
- `npm start` запускает собранный сервер из `dist-server/index.js`. После изменения TypeScript повторите сборку.
- Docker использует тот же собранный сервер и выполняет тесты при сборке образа.

## Первый администратор

Задайте `BOOTSTRAP_ADMIN_USERNAME` и `BOOTSTRAP_ADMIN_PASSWORD` в окружении WebChat или корневом `.env` для Compose. Оба пусты — создание выключено. Пароль: от 12 символов, до 72 байт UTF-8. При запуске после инициализации БД создаётся первый администратор, только если в БД нет администраторов. Существующие записи и пароли не изменяются; занятый логин обычного пользователя не повышается автоматически. Подробности и ручной вариант: [руководство](../docs/getting-started.md#назначить-первого-администратора).

## Авторизация и диалоги

Регистрация принимает имя пользователя и пароль. Базовая роль `employee` и отдел `general` назначаются сервером; переданные клиентом права игнорируются. Сессия хранится в HttpOnly-cookie `session_id` на 30 дней. Доступ к диалогам ограничен владельцем.

Первое сообщение создаёт диалог и отправляется с его ID. Запоздалые ответы и загрузка истории не заменяют содержимое другого выбранного диалога.

Маршруты: `/api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/me`, `/api/conversations`, `/api/chat`. Проверка состояния сервера и подключения к базе: `/health`.

## Администрирование

Пользователям с ролью `admin` доступна вкладка «Администрирование» в шапке. После назначения роли обновите страницу текущей сессии.

- **Обзор:** реальные счётчики пользователей, диалогов, сообщений и активных сессий; состояние сервисов. Обновляется кнопкой «Обновить».
- **Пользователи:** поиск и постраничный список; изменение ролей и подразделений. Понижение последнего администратора запрещено.
- **База знаний:** добавление текста, TXT/Markdown до 2 МБ и PDF до 10 МБ / 50 страниц (до 500 000 символов) с выбором прав доступа и проверкой текста перед сохранением. Для сканов нужен [Docling на CPU](../docs/pdf-upload.md). DOCX и управление уже загруженными документами пока не поддерживаются.

Серверные маршруты `/api/admin/overview`, `/api/admin/users`, `/api/admin/users/:id` и `/api/admin/documents` проверяют сессию и роль. Публичная регистрация не выдаёт административные права.

Для изолированной визуальной проверки после сборки можно запустить `node test/ui-preview.mjs`: порт 3100, только тестовые данные, без доступа к рабочим сервисам. Этот сервер не используется командами `start` и Docker runtime.

Файлы `server.mjs`, `start.mjs`, `session.mjs` и старый интерфейс в `public/` относятся к предыдущей реализации. Текущие команды запуска используют Express и React.
