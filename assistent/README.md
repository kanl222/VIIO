# assistent: LangGraph RAG Agent REST API

Сервис переименован из APIAgent в `assistent`. Рабочий процесс основного агента использует `DOCUMENTS_URL` для поиска и не запускает очередь/индексацию документов. Отдельные процессы `documents` и `document-worker` используют общую библиотеку доменной логики этого Python-пакета; [их запуск и границы](../Documents/README.md). Режим задаётся `SERVICE_ROLE`; Docker Compose настраивает его для каждого контейнера. Для локального основного агента сначала запустите сервис документов.

Отдельный агент программирования вызывается из чата через инструмент `coding_agent`
или напрямую командой `/code`. Настройка: [агент кода](../docs/coding-agent.md).

Клиенты моделей выделены в `src/assistent/models/`: `chat.py` — основная модель и
подключение провайдера, `coder.py` — отдельная модель программирования,
`embeddings.py` — модель эмбеддингов. Переменные окружения по-прежнему описаны в
`config.py`; сборка приложения вызывает эти фабрики из `__init__.py`.

Масштабируемый REST API микросервис на FastAPI для диалогового AI-агента на базе LangGraph с поддержкой сессионной памяти, векторного хранилища Qdrant, локальных моделей **LM Studio** (или Ollama) и развертыванием в Docker.

## Архитектура и принципы разработки

Сервис построен в строгом соответствии с принципами **SOLID**:
- **`src/assistent/interfaces/`** — `Protocol`-абстракции (`IVectorStore`, `IDocumentService`, `IAgentService`, `DocumentMetadata`) для инверсии зависимостей (DIP) и разделения интерфейсов (ISP).
- **`src/assistent/services/`** — бизнес-логика:
  - `DocumentService` — валидация, нарезка текста на чанки (`RecursiveCharacterTextSplitter`) и индексация.
  - `graph_builder.py` — компиляция графа состояний LangGraph (`StateGraph`) с поддержкой инструментов и `MemorySaver` checkpointer.
  - `agent_service.py` — оркестрация сессий диалога и асинхронное взаимодействие с агентом.
- **`src/assistent/tools/`** — инструменты LangChain для поиска и делегирования. В основном приложении модель сначала выбирает `search_knowledge_base` или `coding_agent`; если она пропускает необходимое действие, граф выполняет один запасной вызов. На один ход разрешено максимум три вызова инструментов, включая параллельные. В журнале запасной поиск имеет префикс `knowledge-`, делегирование — `fallback-code-`; остальные вызовы выбирает модель. Приветствия, вычисления и преобразования текста обходят поиск. Права проверяются при каждом обращении. Лексический и семантический поиск объединяются; фрагмент текста выбирается по покрытию значимых слов, а не первому совпадению. Контекст запасного поиска ограничен `RAG_CONTEXT_MAX_CHARS` (по умолчанию 12 000 символов). Основной агент возвращает в `sources` только названные в ответе найденные материалы; при отсутствии ответа список пуст. Это фильтр атрибуции, а не доказательство каждого утверждения. Программный построитель графа сохраняет прежний режим для совместимости; основной сервис явно включает `model_first_tools=True`.
- **`src/assistent/utils/`** — инфраструктурные адаптеры (`QdrantVectorStoreAdapter`) с автосозданием коллекции (cold start) и защитой от гонок.
- **`src/assistent/router.py`** — тонкий HTTP-роутер с Pydantic DTO, неблокирующим вызовом через `anyio.to_thread` и обработкой ошибок.
- **`src/assistent/__init__.py`** — Composition Root (сборка DI-графа с поддержкой провайдеров **LM Studio** и **Ollama**).
- **`src/assistent/runner.py`** — запуск ASGI-сервера Uvicorn.

## Промпты и настройки генерации

`src/assistent/prompts.py` содержит отдельные короткие инструкции консультанта, coder и делегирования. Имена моделей задаются в `.env`; `CHAT_TEMPERATURE`, `CHAT_TOP_P`, `CHAT_MAX_TOKENS` и соответствующие `CODING_*` управляют генерацией. Настройки coder применяются отдельно, даже если `CODING_MODEL` не задан. Диапазоны, значения по умолчанию и команды применения: [руководство](../docs/getting-started.md#настройки-генерации-моделей).

## Требования

Для запуска всей платформы на Windows или Linux используйте [основную инструкцию](../docs/getting-started.md). Там же описаны регистрация, назначение администратора и загрузка TXT/Markdown через веб-интерфейс. Ниже приведены команды для отдельного assistent.

- Python `>= 3.12`
- Менеджер пакетов [uv](https://docs.astral.sh/uv/)
- Запущенный локальный сервер [LM Studio](https://lmstudio.ai/) с моделями чата и эмбеддингов:
  ```bash
  lms server start
  ```
  *Примеры установленных локальных моделей:*
  - LLM: `qwen/qwen3-4b-2507`, `google/gemma-4-e2b`, `qwen/qwen3.5-9b`
  - Embeddings: `text-embedding-nomic-embed-text-v1.5`, `text-embedding-multilingual-e5-base`
- Векторная база данных Qdrant (локально или через Docker)

## Локальный запуск

1. **Клонирование репозитория и переход в директорию проекта:**
   ```bash
   cd assistent
   ```

2. **Запуск сервера LM Studio:**
   ```bash
   lms server start
   ```

3. **Создание файла конфигурации `.env`:**
   ```bash
   cp .env.example .env
   ```

4. **Установка зависимостей с помощью `uv`:**
   ```bash
   uv sync
   ```

5. **Запуск сервиса assistent:**
   ```bash
   uv run assistent
   ```
   Сервер запустится по адресу: `http://localhost:8000`. Интерактивная Swagger-документация: `http://localhost:8000/docs`.

## Запуск в Docker Compose

Используйте единственный корневой `docker-compose.yml` из каталога VIIO. Прежняя отдельная Compose-конфигурация внутри пакета удалена: без Documents API и worker она больше не описывала рабочую систему.

Из корня VIIO запускайте общий стек по основной инструкции. Команда:

```bash
docker compose up -d --build
```

- Сервис Qdrant доступен на порту `6333`
- Сервис assistent доступен на порту `8000`
- Documents API доступен на порту `8002`, консультант — на `8001`
- Подключение к хостовому серверу LM Studio настроено через `http://host.docker.internal:1234/v1`

Остановка контейнеров:
```bash
docker compose down
```

## Спецификация API

### 1. Проверка состояния: `GET /health`

**Запрос:**
```bash
curl -X GET http://localhost:8000/health
```

**Ответ (200 OK):**
```json
{
  "status": "healthy",
  "provider": "lmstudio",
  "model": "qwen/qwen3-4b-2507",
  "documents_count": 12
}
```

---

Защищённые запросы ниже предназначены для серверной интеграции. Они требуют заголовка `X-Internal-Token` со значением `INTERNAL_API_KEY`, настроенным в assistent. В Bash перед выполнением примеров задайте переменную `INTERNAL_API_KEY` в текущем терминале; она не загружается из `.env` автоматически. Не передавайте этот токен в клиентский браузерный код. Примеры `curl` используют синтаксис Bash; для обычной загрузки на Windows используйте веб-форму из основной инструкции.

### 2. Добавление документа в базу знаний: `POST /api/v1/documents`

**Запрос:**
```bash
curl -X POST http://localhost:8000/api/v1/documents \
  -H "Content-Type: application/json" \
  -H "X-Internal-Token: $INTERNAL_API_KEY" \
  -d '{
    "title": "Регламент возврата товара",
    "content": "Возврат товара надлежащего качества возможен в течение 14 дней с момента покупки при сохранении товарного вида и чека.",
    "metadata": {
      "source": "wiki",
      "department": "support"
    }
  }'
```

**Ответ (201 Created):**
```json
{
  "document_id": "doc-a1b2c3d4",
  "title": "Регламент возврата товара",
  "chunks_count": 1,
  "status": "indexed"
}
```

---

### 3. Диалог с агентом: `POST /api/v1/chat`

**Запрос (первое сообщение в новой сессии):**
```bash
curl -X POST http://localhost:8000/api/v1/chat \
  -H "Content-Type: application/json" \
  -H "X-Internal-Token: $INTERNAL_API_KEY" \
  -d '{
    "message": "В течение какого срока я могу вернуть товар?"
  }'
```

**Ответ (200 OK):**
```json
{
  "reply": "Согласно регламенту возврата, вы можете вернуть товар надлежащего качества в течение 14 дней с момента покупки.",
  "thread_id": "9f3c1b64-5820-410e-8ea2-36c927f6be32"
}
```

**Последующий запрос с сохранением контекста диалога (`thread_id`):**
```bash
curl -X POST http://localhost:8000/api/v1/chat \
  -H "Content-Type: application/json" \
  -H "X-Internal-Token: $INTERNAL_API_KEY" \
  -d '{
    "message": "А что нужно сохранить для возврата?",
    "thread_id": "9f3c1b64-5820-410e-8ea2-36c927f6be32"
  }'
```
