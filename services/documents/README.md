# Documents

Самостоятельный сервис базы знаний VIIO. Пакет `viio_documents` находится в `Documents/src`, имеет собственные зависимости, lock-файл, тесты и Dockerfile. Импортов пакета Assistent нет. Оба агента используют только HTTP-контракт.

- `documents` обслуживает каталог, ACL, версии, скачивание и управление очередью; прежние поисковые URL проксирует в `rag`.
- `rag` — отдельный FastAPI-процесс для поиска, ранжирования и подготовки контекста, со своим контейнером и журналом. Читает каталог в транзакциях read-only и Qdrant по ключу чтения; не имеет тома оригиналов, очереди и миграций.
- `document-worker` выполняет извлечение текста, индексацию, публикации и восстановление индекса.
- `pdf-worker` выполняет локальный разбор PDF через Docling CPU/OCR.

Поддерживаются PDF, DOCX, ODT, TXT, Markdown и исходники кода. Оригиналы сохраняются отдельно от текста поиска. PDF сохраняет Markdown Docling, DOCX/ODT/TXT проходят очистку пробелов и служебных символов; исходники и произвольный Markdown сохраняют форматирование. Предпросмотр извлекает текст без индексации; для хранения оригинала используйте массовую загрузку, в том числе одного файла. По умолчанию до 50 файлов: PDF до 32 МБ, остальные до 10 МБ; веб-прокси ограничивает суммарный запрос 50 МБ.

В режимах `PDF_ENGINE=auto` и `docling` все PDF проходят Docling, включая файлы с текстовым слоем. `pypdf` — явный упрощённый режим без анализа макета и OCR. Лимиты по умолчанию: 200 страниц, 500 000 символов и 1800 секунд. CPU-разбор больших руководств может занимать десятки минут. Для штатной загрузки используйте фоновую очередь: PDF ожидает проверки текста, затем индексируется подтверждённая редакция. Структурный JSON Docling со страницами и таблицами остаётся в журнале задания для проверки исходного разбора.

Фрагменты Markdown не смешивают соседние разделы и содержат путь заголовков в `section_path`. Заголовки повторяются в продолжениях; большие таблицы делятся по строкам с повторением шапки, слишком большие строки дополнительно ограничиваются размером фрагмента. Разбиение применяется и к одобренным внешним публикациям. Уже загруженный текст автоматически заново из оригиналов не извлекается.

DOCX/ODT экспортируют таблицы в Markdown: первая строка используется как шапка и повторяется в продолжениях. Символы `|` внутри ячеек экранируются, переносы внутри ячейки сохраняются как `<br>`. Разбиение `sections-v2` сохраняет соседние разделы без текста и не принимает строки внутри ограждённых блоков кода за таблицы. Для уже загруженных материалов эти изменения требуют повторного извлечения и индексации.

При заданных языках `rus`/`eng` сообщение Tesseract `OSD failed: Too few characters` означает неудачное определение ориентации фрагмента. В установленном Docling 2.142.1 OCR после него продолжается с поворотом 0°. Доступность `/health` не подтверждает качество распознавания; проверяйте результат и статус задания.

Существующие PostgreSQL и Docker-том с оригиналами сохраняются. Внутренняя публичность документа не означает публикацию для внешнего консультанта. Внешний агент получает только явно одобренные снимки; приватный оригинал проверяется отдельно.

## Запуск

Сборка: `docker compose build document-worker rag` из корня проекта. Образ `viio-documents` используется API и worker, `viio-rag` — поисковым процессом. Общий пакет сохраняет одну реализацию ACL и ранжирования без копирования кода. Настройка ключей, отдельные роли БД, миграции, Windows/Linux и production override описаны в [инструкции выпуска A](../docs/release-a-2026-10-28.md).

При включённой диагностической конфигурации сборка и запуск должны использовать те же файлы Compose: `docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.diagnostics.yml build document-worker`. Этот вариант выбирает образ `viio-documents:diagnostics`; сборка только `latest` не обновляет уже выбранный диагностический образ.

Для разработки без Docker из каталога Documents выполните `uv sync`. В двух отдельных терминалах:

PowerShell:

```powershell
$env:SERVICE_ROLE='document-worker'
uv run uvicorn viio_documents:create_app --factory --port 8003
```

```powershell
$env:SERVICE_ROLE='documents'
$env:DOCUMENT_WORKER_URL='http://localhost:8003'
uv run uvicorn viio_documents:create_app --factory --port 8002
```

Linux:

```sh
SERVICE_ROLE=document-worker uv run uvicorn viio_documents:create_app --factory --port 8003
SERVICE_ROLE=documents DOCUMENT_WORKER_URL=http://localhost:8003 uv run uvicorn viio_documents:create_app --factory --port 8002
```

Для обоих процессов нужны одинаковые подключения к каталогу/хранилищу и отдельные ключи согласно инструкции. Для production обязательно SECURE_RUNTIME=true. Assistent запускается из своего каталога с DOCUMENTS_URL=http://localhost:8002 и DOCUMENTS_READ_KEY. Роль documents/document-worker больше не запускается через пакет assistent.

## Обслуживание

Сценарии находятся в `Documents/scripts`. Доверенный импорт и синхронизацию индекса выполняйте в document-worker с его runtime-правами; миграции и выдачу ролей — отдельной учётной записью развёртывания:

```sh
docker cp RAG/scripts/sync_public_index.py viio_document_worker:/tmp/sync_public_index.py
docker exec viio_document_worker python /tmp/sync_public_index.py
```

Секреты не передавайте в командной строке и не коммитьте `.env`. Полный плановый откат и резервное копирование описаны в инструкции выпуска A.
